# 引导式场景设计公式

> 这份文档给**讲师**和**二次开发场景**的人看：引导式场景是怎么设计出来的？为什么要这样设计？怎么判断一个场景"够不够好"？
>
> **引导式场景 ≠ 案例**。案例告诉你"发生了什么"，引导式场景逼你"做一次统筹决策"。

---

## 一、引导式场景的核心五元素

一个好场景 = **角色 + 任务 + 关键节点 + 留白 + 可迁移原则**。

### 1. 角色（有"摩擦"的真人）

不是"一个管理者"，而是"一个做了8年、急脾气、数据驱动、上个月因为忽视老师傅经验导致项目返工的互联网公司技术Leader"。

**为什么要有性格**：演练时，"急脾气"会让角色本能选择"自己扛"——讲师要引导学员识别这种"不信任AI也不信任人"的问题。

**角色的四要素**：
- **背景信息**：公司规模、行业、岗位、本月统筹任务
- **教学对象**：团队成员构成、过往人机协作表现
- **性格特征**：急/慢/完美主义/控制狂/数据控/关系导向（选 1-2 个）
- **过往经验**：做过的人机协作项目、踩过的坑、对智能体的既有态度

### 2. 任务（具体的、可失败的）

不是"统筹一下团队工作"，而是"本周五要给CEO汇报Q3季度总结，你需要协调3个部门的数据分析师，在48小时内完成一份包含人机协作效率的汇报材料，其中AI部分的数据需要你判断可信度"。

**任务三要素**：
- **交付物**：是什么（方案/汇报/决策/协调结果）
- **时间约束**：什么时候交付、有没有时间迭代
- **验收标准**：谁来评估好坏（老板/客户/数据/行为改变）

**任务设计要避免"开放式"**：不要让学员自由发挥，要给出具体场景让学员判断"人还是机"。

### 3. 关键节点（统筹决策停在哪）

每个场景只有一个核心关键节点——**统筹决策在哪里停**。

比如：
- 第一模块（共同语境）卡点：角色认为"大家都知道目标"——但实际上3个部门对"Q3重点"的理解完全不一样
- 第三模块（人机判断）卡点：角色把所有数据整理都交给AI——但没判断AI哪些判断可信
- 第四模块（信任建立）卡点：AI给了建议，角色直接用——没验证假设前提

**一个场景只设一个关键节点**。多节点会让场景"散"——学员不知道在练哪个统筹方法。

### 4. 留白提问（开放、引发思考）

不是"对不对""要不要用AI"，而是"AI给了这个建议，你的第一反应是相信、质疑、还是验证？你这个反应背后的假设是什么？"

**留白提问的三个特征**：
- **没有标准答案**——决策之后每个人都有不同的理由
- **指向真实经验**——让学员从自己工作里"挖"出判断依据
- **给"想"留时间**——讲师要刻意停 30 秒不接话

**反例**："大家觉得AI靠谱吗？" "要不要用智能体？"——这些是**关闭思考**的提问，不是留白提问。

### 5. 可迁移原则（一句话点透）

每个场景最后必须有一句"可迁移原则"——学员学完之后回到自己的工作能直接用的话。

比如：
- "AI的建议不是答案，是假设——你的判断力在于验证假设，而不是接受建议。"
- "统筹的本质不是控制，是对齐——对齐团队对目标的理解，对齐人机各自的能力边界。"
- "信任不是相信AI不会错，而是知道它错的时候你怎么发现。"

**可迁移原则的检验**：把场景的"行业"标签去掉，这句话还成立吗？成立就是好的可迁移原则。

## 二、案例 vs 引导式场景的本质差异

| 维度 | 案例（传统） | 引导式场景（本库） |
|------|------------|-----------------|
| 目的 | 传递信息 | 引发决策和行动 |
| 主角 | 讲师 | 学员 |
| 结束点 | 讲完了 | 学员做出选择 |
| 输出 | "我学到了..." | "我打算下次..." |
| 评估 | 讲师讲得好不好 | 学员有没决策 |
| 设计核心 | 内容编排 | 留白点选择 |

**最关键差异**：案例的终点是"听完了"，引导式场景的终点是"做了选择"。

## 三、留白点选择的 3 种典型模式

留白不是"随便停一下"，留白点有讲究：

### 模式 1：核心概念之后（最常用）

**什么时候用**：你刚讲完一个统筹方法 / 人机判断框架 / 信任建立模型

**怎么做**：
- 讲完停下
- 留 30 秒（讲师不要接话）
- 提问："这个框架用在你上个月那个项目里，哪个环节你会先试？"

**原理**：统筹方法必须落到具体任务上才"活"。留白给学员"挂钩"的时间。

### 模式 2：冲突点 / 反常识处

**什么时候用**：你刚讲了一个违反学员直觉的观点（比如"AI做得比人好时，更要人参与"）

**怎么做**：
- 讲完停下
- 不要问"对不对"（会被礼貌性回应）
- 提问："这和你之前'AI做得好就交给AI'的做法有什么不同？你会怎么调整？"

**原理**：反常识会引发认知冲突，冲突必须被处理（说出来）才完成学习。

### 模式 3：关键选择前

**什么时候用**：学员即将做一个关键决策（要不要引入AI、要不要信任AI的建议、要不要调整分工）

**怎么做**：
- 把选择摆出来
- 留 60 秒（比模式 1 久）
- 提问："如果是你，你怎么选？你的判断依据是什么？"

**原理**：选择前的留白是"内化"的过程——学员要"过一遍"自己的判断逻辑。

## 四、四层提问清单（按提问深度递进）

所有场景的"四层提问"都按这个框架设计，**学员拿到场景就知道问什么**：

| 层级 | 提问类型 | 学员在做什么 | 示例 |
|------|---------|------------|------|
| 🥇 事实层 | 召回/识别 | 复述刚讲的统筹要点 | "这个场景里，AI做了哪三件事？" |
| 🥈 感受层 | 联想/共情 | 联系自己经验 | "你上次遇到'相信AI还是相信自己'是什么时候？" |
| 🥉 原则层 | 抽象/归纳 | 提炼方法 | "什么时候该信AI，什么时候该信人？" |
| 🏅 行动层 | 决策/应用 | 落地下一步 | "你下次遇到类似场景，会先做什么？" |

**关键规则**：
- 不允许跳过事实层直接到行动层（学员还没"懂"就让他"做"是无效的）
- 事实层可以快速过（30秒），但要留
- 行动层必须有具体时间锚点（"下周一""下个月""下次"）

**为什么是 4 层不是 3 层**：
- 统筹决策需要"从信息到判断"的完整链条——事实层确认信息、感受层激活经验、原则层提炼规律、行动层落地决策
- 4 层是"从知道到做到"的最短路径

## 五、互动流程（个人→两人→全班）的标准结构

所有场景的"互动流程"按 90-180-480 秒设计（个人 90 秒 / 两人 3 分钟 / 全班 8 分钟）：

```
个人（90秒）→ 两人（3分钟）→ 全班（8分钟）
 ↓              ↓                ↓
独立思考       和同桌对谈       分享给全班
"我先想清楚"   "我们俩先碰一下"  "看看其他人怎么想"
```

**为什么是这个节奏**：
- 90 秒个人思考 = 给内向学员"先形成判断"的机会
- 3 分钟两人对谈 = 让观点先"小范围碰撞"再"大范围曝光"
- 8 分钟全班讨论 = 提取共性、暴露分歧、形成行动

**讲师在每个阶段的核心动作**：
| 阶段 | 讲师做什么 | 讲师不做什么 |
|------|----------|------------|
| 个人 | 计时、保持安静 | 不巡视、不接话 |
| 两人 | 计时、提示"对谈" | 不指定谁先说 |
| 全班 | 计时、记录关键点 | 不评价对错、不抢话 |

## 六、7 个常见场景设计陷阱

设计场景时最容易掉的坑：

### 陷阱 1：场景变成了"知识讲解"
❌ "在这个场景里，我们用人机判断的方法..."
✅ 通过角色的决策过程，让方法自然呈现

### 陷阱 2：场景变成了"道德说教"
❌ "小明因为不信任AI，导致效率低下，我们应该..."
✅ 呈现"不统筹的代价"，让学员自己判断

### 陷阱 3：场景变成了"完美示范"
❌ 角色在人机协作里"无所不能"
✅ 角色在高效版本里**有纠结**——比如"我本来也想直接用AI，但意识到..."

### 陷阱 4：行业味道不够
❌ 把"互联网产品"去掉之后还能用——说明行业细节不足
✅ 包含具体岗位、KPI、行业术语、典型工作场景

### 陷阱 5：留白点选错
❌ 在"小知识点"之后留白——学员没什么可想的
✅ 在"核心判断 / 反常识 / 关键选择"前留白

### 陷阱 6：互动流程时间不匹配
❌ 60 秒个人思考 + 30 秒全班讨论——个人思考没做完就到大组
✅ 个人 90 秒、两人 3 分钟、全班 8 分钟——让思考逐步"暴露"

### 陷阱 7：四层提问顺序错乱
❌ 上来就问"你打算怎么做"（行动层）——学员没基础就行动是空话
✅ 事实→感受→原则→行动——按顺序递进

## 七、场景质量的"自检清单"

每个场景交付前，对照检查：

| 检查项 | 通过标准 |
|--------|---------|
| 角色卡有"摩擦"？ | 有具体性格特征，不是"一个管理者" |
| 任务是可失败的？ | 给出具体的失败后果，不是"做得不够好" |
| 关键节点明确？ | 一句话能说清在练哪个统筹方法 |
| 留白提问有"钩"？ | 能引发学员回忆、联想、决策，不是"对不对" |
| 互动流程有节奏？ | 个人 90s + 两人 3min + 全班 8min |
| 四层提问齐全？ | 事实→感受→原则→行动，按顺序 |
| 可迁移原则够锐？ | 一句话能在其他场景复用 |
| 对应课程知识点明确？ | 标注属于第几模块/第几方法 |
| 行业气味足？ | 去掉行业标签后场景就不成立 |
| 人机元素有体现？ | 场景里明确涉及智能体介入判断或信任问题 |

**不通过的场景，不要交付**。

## 八、场景的"行业气味"

不同行业的"场景味道"完全不同，这是按行业分版本的核心价值：

| 行业 | 场景的"味道" | 不能写成的样子 |
|------|------------|--------------|
| 制造业 | 现场、对账、责任、留痕 | 不能写成"白领坐办公室" |
| 互联网产品 | 速度、迭代、用户、数据 | 不能写成"按部就班" |
| 电商零售 | 流量、转化、爆款、热点 | 不能写成"长期主义" |
| 销售客户成功 | 关系、方案、跟进、关单 | 不能写成"标准流程" |
| 培训HR | 学员、需求、效果、内化 | 不能写成"完成任务" |
| 财务法务 | 准确、合规、风险、留痕 | 不能写成"效率优先" |
| 教育咨询 | 知识、案例、引导、深度 | 不能写成"快速解决" |
| 医疗健康 | 严谨、共情、循证、伦理 | 不能写成"强势说服" |

**自检问题**：把这个场景的"行业"标签去掉，还成立吗？如果去掉之后还能用，说明行业味道不够，要重写。

## 九、扩展：如何为本企业定制场景

### 第 1 步：选定行业版本作为模板
比如你是制造业，选"制造业_场景集"作为基础。

### 第 2 步：替换"角色卡"
- 公司名换成你公司
- 岗位换成你公司的对应岗位
- 团队成员换成你公司真实的团队构成
- 性格特征问学员自己（"你觉得你团队里的人是什么性格"）

### 第 3 步：替换"背景任务"
收集学员最近 1 个月真实做的统筹任务，挑出 2-3 个最有代表性的。

### 第 4 步：替换"关键节点"
问学员"这次统筹你失败/成功的是哪一步？"—— 关键节点就在那。

### 第 5 步：让学员自己写高效能版
把 ❌ 失败版给学员，让他们**对照**写 ⚠️ 改进版和 ✅ 高效能版。**这是最强的学习方式**。

---

> **设计场景的最高原则**：学员演完一个场景后，应该对自己的统筹方式有一点点"原来我一直在单打独斗"的反思。
