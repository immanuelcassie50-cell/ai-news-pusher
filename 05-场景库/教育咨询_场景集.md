# 教育咨询_场景集

> **行业标签**：教育 / 咨询 / 知识工作者
> **主角色**：陈静（麦肯锡 高级咨询顾问 & 项目统筹人）
> **设计目的**：教育咨询的"知识密度大、怕讲错、决策压力大"特征，让"人工作业"和"人机协作"的统筹差异在高认知负荷场景下被放大。

---

## 行业概览

### 典型岗位
- 咨询顾问 / 高级咨询顾问 / 合伙人
- 课程设计师 / 教学设计师
- 培训师 / 引导师 / 促动师
- 企业高管教练 / 领导力发展
- 研究分析师 / 知识管理

### 这个行业的"统筹难点"
- **知识密度大**：每个项目都是新领域，要快速学习
- **怕讲错**：客户/学员在场，错误代价高
- **决策压力大**：建议被采纳才能体现价值
- **人机边界模糊**：AI分析报告、AI生成PPT、AI写框架——哪些该用AI？
- **表达严谨**：不爱用模糊词汇，要精确

### 这个行业的"专属坑"
- ❌ "我先研究研究"——过度准备，错过Deadline
- ❌ "这个框架是业界标准的"——不会灵活变通
- ❌ "AI分析肯定没我专业"——拒绝AI辅助
- ❌ "我讲完了，有什么问题？"——单向讲解
- ❌ 报告"大而全"——没有重点，没有建议

### 行业气味关键词
> 假设驱动、框架思考、数据验证、专家访谈、焦点小组、MECE原则、电梯演讲、storyline、人机协同报告、GPT辅助研究

## 场景 1：周一——接到项目，先对齐"问题定义"

### 📋 背景任务

周一上午，陈静收到项目经理（合伙人）的邮件：

> **主题**：零售客户数字化转型项目启动
> **正文**：@陈静 你统筹这个项目。客户是某头部服装品牌，核心问题是"库存周转率低"。先做现状诊断，12周后给建议。
> 评估方式：客户的库存周转率在项目结束后的改善情况。

陈静立刻开始列"现状诊断"的大纲：
1. 库存现状分析（各品类周转率）
2. 供应链现状分析（采购/物流/仓储）
3. 数字化现状分析（系统/工具/数据）
4. 竞争对标分析

她发给项目经理看，项目经理回：

> "你这个框架是标准的，但客户真正的问题是什么，你清楚吗？"

陈静愣了一下——她默认了"库存周转率低"就是问题，但没追问"为什么低"。

**问题**：陈静**没验证"问题定义"**——她接受了客户给的"症状"，没深挖"病因"。

### 🛑 关键节点

**第一模块·共同语境对齐**：陈静接受了"库存周转率低"这个症状，没追问真正的问题。

**问题**：陈静没有"追问5个为什么"的习惯。

### 💭 留白提问

> "客户说'库存周转率低'——这是问题，还是问题的症状？你怎么知道？"
>
> **个人思考 90 秒**

### 🤝 互动流程（个人 → 两人 → 全班）

**个人（90 秒）**：写下你会怎么追问"库存周转率低"——至少问3个"为什么"

**两人（3 分钟）**：和同桌对一下——你问的"为什么"和同桌的一致吗？

**全班（8 分钟）**：
- 每组 1 条"我们组追问出的真正问题"
- 讲师记录在白板
- 讲师点睛：**"症状"不是"问题"——追问5个为什么，才能找到真正的病因**

### 🎯 四层提问清单

| 层级 | 提问 | 学员在做什么 |
|------|------|------------|
| 🥇 事实层 | 客户说"库存周转率低"——具体数字是多少？行业平均是多少？ |
| 🥈 感受层 | 你上次遇到"客户说的需求不是真正需求"是什么时候？ |
| 🥉 原则层 | 为什么"症状"不等于"问题"？ |
| 🏅 行动层 | 你**今天下午**会约谁追问问题定义？ |

### 💡 可迁移原则

> **客户说的"症状"不是"问题"——追问5个为什么，找到真正的病因。**

## 场景 2：周二——AI数据分析报告出来了，用不用？

### 📋 背景任务

周二下午，分析师小王用AI工具跑了一份库存数据分析报告：

> **AI分析结论**：
> - A品类周转率低于行业平均30%
> - B品类库存天数超标50%
> - C品类预测误差大（实际误差±25%）
> **建议**：优先改善A品类，可以提升整体周转率15%

陈静看着这个结论，总觉得哪里不对。

她问小王："这个数据哪来的？"

小王说："AI从客户系统里自动拉的。"

陈静追问："AI有没有可能拉错数据？"

小王说："应该不会吧……"

**问题**：陈静**不信任AI的数据分析结论**——但她不知道怎么验证。

### 🛑 关键节点

**第三模块·人机判断 + 第四模块·信任建立**：AI给了分析建议，陈静不知道该不该信。

**问题**：陈静没有"验证AI结论"的框架。

### 💭 留白提问

> "AI给了这个分析结论——你的第一反应是相信、质疑、还是验证？你的反应背后，假设是什么？"
>
> **个人思考 90 秒**

### 🤝 互动流程

**个人（90 秒）**：写下你会怎么验证这个AI结论——步骤是什么？

**两人（3 分钟）**：对一下——你验证的步骤能覆盖"数据错了怎么办"的情况吗？

**全班（8 分钟）**：
- 抽 3 个组分享
- 讲师点睛：**"用AI结论"不是终点，"验证数据来源"才是起点——数据错了，结论再漂亮也是假的**

### 🎯 四层提问清单

| 层级 | 提问 |
|------|------|
| 🥇 事实层 | AI的数据来源是什么？客户系统里有这个数据吗？ |
| 🥈 感受层 | 你上次用AI数据结果出问题是什么时候？ |
| 🥉 原则层 | 为什么"验证数据来源"比"验证分析逻辑"更重要？ |
| 🏅 行动层 | 你**现在**决定：怎么验证这个AI结论？ |

### 💡 可迁移原则

> **数据是结论的根基——AI可以分析，但人必须验证数据来源，否则结论无意义。**

## 反例场景：❌ "纯人工"型咨询统筹者（识别问题用）

### 📋 背景

陈静的同事老刘，另一个项目负责人，做项目的方式是：AI工具挺好，但我还是习惯自己来。

老刘的选择是：
- 不用AI数据分析——"数据自己看才放心"
- 不用AI生成PPT——"框架自己搭才靠谱"
- 不用AI转录访谈——"自己记才记得住"

结果：
- 每个项目都加班到很晚
- 报告"很扎实"但"没新意"
- 客户评价："老刘很专业，但建议有点常规"

老刘说："AI的东西不放心，还是自己来靠谱。"

**学员的反馈**：
- "刘总很专业，但效率太低了"
- "有些分析感觉AI能做得更快"

### 🛑 关键问题

**老刘的"靠谱"是假把式**——他**用"自己来"掩盖了对AI的不信任**，既累死自己，又没发挥AI的价值。

### 💭 留白提问
