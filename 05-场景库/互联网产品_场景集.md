# 互联网产品_场景集

> **行业标签**：互联网 / 产品 / 技术 / 增长
> **主角色**：张明阳（字节跳动 增长负责人 & 跨部门协调人）
> **设计目的**：互联网产品的"快节奏、术语密、抽象概念"特征，让"人工作业"和"人机协作"的统筹差异在高压场景下被放大。

---

## 行业概览

### 典型岗位
- 产品经理 / 增长负责人 / 运营负责人
- 技术 Leader / 架构师
- 数据分析师 / 算法工程师
- AI 产品经理 / 智能体产品设计
- 跨部门协调人 / 项目负责人

### 这个行业的"统筹难点"
- **术语密度高**：UV/DAU/ARPU/留存/漏斗/北极星指标——跨部门对话时"鸡同鸭讲"
- **节奏快**：双周迭代，没有时间慢慢对齐
- **人机边界模糊**：AI辅助写作、代码生成、数据分析——哪些该交给AI？
- **多团队协作**：产品、技术、设计、运营、市场——谁对什么负责？

### 这个行业的"专属坑"
- ❌ 用"显然""大家都知道"开头——其实没人知道
- ❌ 认为"我讲过了就等于对齐了"——其实没有
- ❌ 把AI建议当答案——不验证假设前提
- ❌ 人机分工一刀切——要么全自己做，要么全给AI
- ❌ 忽视"信任建立"——直接用AI结果，不问"它怎么得出这个结论"

### 行业气味关键词
> 迭代、A/B测试、北极星、用户增长、漏斗转化、留存、ARPU、增长飞轮、PMF、Aha时刻、人机协同、智能体、Copilot

## 场景 1：周四上午——接到汇报任务，先对齐"共同语境"

### 📋 背景任务

周四上午10点，张明阳收到增长总监的邮件：

> **主题**：周五CEO汇报Q3增长情况
> **正文**：@张明阳 你统筹一下。产品、技术、数据三个部门都要汇报，你负责汇总"人机协作效率"这一节。
> 评估方式：CEO问的每一个问题，都要有人能答。

张明阳立刻拉群："各位，周五CEO汇报，每人准备3页PPT。"

5分钟后，产品经理回复："明白，我准备留存那块。"
10分钟后，数据分析师回复："我准备ARPU那块。"
技术Leader没回复。

**他要面对的**：
- 3个部门对"人机协作效率"的理解完全不一样——产品觉得是"AI辅助了多少工作"、技术觉得是"代码生成率"、数据觉得是"分析效率提升"
- 技术Leader没回复——他是"技术出身不爱说话"的那种人
- 周五就要汇报，48小时

### 🛑 关键节点

**第一模块·共同语境对齐**：张明阳认为"我拉群了=对齐了"——但实际上3个部门连"人机协作效率"的定义都没对齐。

**问题**：张明阳没意识到"我讲过了"不等于"对方懂了"。

### 💭 留白提问

> "你拉群说了'准备3页PPT'——但产品、技术、数据三个部门理解的'人机协作效率'是同一件事吗？如果不是，你怎么办？"
>
> **个人思考 90 秒**

### 🤝 互动流程（个人 → 两人 → 全班）

**个人（90 秒）**：写下"如果三个部门对'人机协作效率'定义不同，你的第一个动作是什么？"

**两人（3 分钟）**：和同桌对一下——你写的动作和对方写的差在哪？

**全班（8 分钟）**：
- 每组 1 条"我们组的第一个动作"
- 讲师记录在白板
- 讲师点睛：**"对齐"不是"我说了"，是"对方能用他的话复述一遍"——先确认定义，再分工**

### 🎯 四层提问清单

| 层级 | 提问 | 学员在做什么 |
|------|------|------------|
| 🥇 事实层 | 产品、技术、数据三个部门，**分别认为**"人机协作效率"是什么？ | 召回 |
| 🥈 感受层 | 你上次遇到"我说A对方理解成B"是什么时候？ | 联想 |
| 🥉 原则层 | 为什么"定义没对齐"会在后面造成返工？ | 抽象 |
| 🏅 行动层 | **今天下午**你会约谁先对齐定义？ | 决策 |

### 💡 可迁移原则

> **"我讲了"不等于"对齐了"——先确认对方用自己的话复述了你的意思，再分工。**

## 场景 2：周四下午——目标拆解，判断哪些该人做、哪些该AI做

### 📋 背景任务

张明阳终于约到了技术Leader对面沟通。

技术Leader说："我这边能给的，就是代码生成率——GitHub Copilot用了多久、生成了多少行代码、覆盖了多少需求。"

张明阳问："那'效率提升'呢？"

技术Leader说："这个AI没法量化，得人填。"

张明阳回到工位，开始拆解任务：
1. 留存数据 → 数据分析师做（人）
2. ARPU分析 → 数据分析师做（人）
3. 代码生成率 → 技术Leader给（数据）
4. 人机协作效率 → ??? （AI还是人？）

他发现：前3项都有人接，第4项"人机协作效率"没人接——因为不知道算什么、怎么算、谁来算。

**问题**：张明阳**没判断清楚"人机边界"**——哪些该用AI算，哪些必须人判断。

### 🛑 关键节点

**第三模块·人机判断**：张明阳本能地想"这个交给AI算了"——但没验证AI能不能做。

**问题**：张明阳对AI的能力边界没有清晰判断。

### 💭 留白提问

> ""人机协作效率"这个指标——AI能算出来吗？还是必须人来定义和判断？"
>
> **个人思考 90 秒**

### 🤝 互动流程

**个人（90 秒）**：在纸上画一下——哪些环节AI能做、哪些环节必须人做？

**两人（3 分钟）**：对一下——你画的和同桌画的一致吗？

**全班（8 分钟）**：
- 抽 2-3 个组分享
- 讲师点睛：**"AI能算"不等于"AI该算"——必须人定义的指标，AI算出来也没意义**

### 🎯 四层提问清单

| 层级 | 提问 |
|------|------|
| 🥇 事实层 | "人机协作效率"这个指标，AI能算出哪几个数字？ |
| 🥈 感受层 | 你上次让AI算一个指标，结果发现它算的不对，是什么时候？ |
| 🥉 原则层 | 什么样的指标必须人定义，什么样的指标AI可以算？ |
| 🏅 行动层 | 你**现在**决定：谁来做"人机协作效率"这个指标的定义？ |

### 💡 可迁移原则

> **AI能算的不等于AI该算——先有人定义"算什么"，再决定"谁来算"。**

## 场景 3：周四晚上——AI给了数据分析建议，我要信多少？

### 📋 背景任务

周四晚上9点，数据分析师发来一份分析报告：

> **Q3人机协作效率分析**

> - AI辅助设计产出：47张运营图
> - 内容生成效率提升：2.3倍
> - **结论**：人机协作效率显著提升，建议Q4继续扩大AI使用范围。

张明阳看着这个结论，总觉得哪里不对。

他想问数据分析师，但对方已经下班了。

**问题**：张明阳**不信任AI的分析结论**——但他不知道该怎么验证。

### 🛑 关键节点

**第四模块·信任建立**：AI给了建议，张明阳第一反应是"这个结论靠谱吗"——但他不知道怎么验证。

**问题**：张明阳没有建立"验证AI结论"的习惯。

### 💭 留白提问

> "AI给了这个分析结论——你的第一反应是相信、质疑、还是验证？你的反应背后，假设是什么？"
>
> **个人思考 90 秒**

### 🤝 互动流程

**个人（90 秒）**：写下你验证这个AI结论的3个步骤

**两人（3 分钟）**：对一下——你验证的步骤和同桌的差在哪？

**全班（8 分钟）**：
- 抽 3 个组分享
- 讲师点睛：**"信任AI"不是"相信AI不会错"，是"知道它错的时候你怎么发现"——验证假设前提**

### 🎯 四层提问清单

| 层级 | 提问 |
|------|------|
| 🥇 事实层 | AI的这份报告，**假设前提**是什么？ |
| 🥈 感受层 | 你上次"信了AI的结果，后来发现有问题"是什么时候？ |
| 🥉 原则层 | 为什么"验证假设前提"比"验证数字本身"更重要？ |
| 🏅 行动层 | 你**现在**打算怎么验证这份报告？ |

### 💡 可迁移原则

> **AI的建议不是答案，是假设——你的判断力在于验证假设，而不是接受建议。**

张明阳的同事王海，也是增长负责人。周五汇报，CEO问了同样的问题："2.3倍怎么算的？"
