## 一、文档结构体系分析

### 1.1 文档层级架构对比

| 文档类型 | 层级数 | 标题层级示例 |
|---------|--------|-------------|
| 课程导引 | 3级 | 一级(全程导览)、二级(两天学习地图)、三级(场景卡) |
| 教学模块 | 4级 | 一(第一部分)、二级(模块一/模块二)、三级(1.1/1.2)、四级(改写练习) |
| 工具表单 | 3级 | 一(正面/背面)、二级(问题类型)、三级(举例/特征) |
| 练习题库 | 4级 | 一(题目一)、二级(讨论问题)、三级(参考答案)、四级(判断维度表) |
| 课程大纲 | 4级 | 一(第一章)、二级(模块学习目标)、三级(活动序列)、四级(序号) |
| 学员手册 | 5级 | 一(第一层)、二级(第一章 习惯1)、三级(知识点1.1)、四级(面孔一)、五級(正文) |

**规律发现**：
- 内容越厚（学员手册1659行），层级越深，以容纳密集知识框架
- 工具表单层级最浅（3级），因为核心是"可操作性"，浅层级便于快速查阅
- 所有文档均采用"总-分-总"结构：开头全局概览 → 中间分模块展开 → 结尾总结产出

### 2.3 关键认知框的标准格式

**文档2中的关键认知框示例：**
```

```

**格式规范：**
- 标记符号：💡 + "**关键认知**"
- 内容结构：原理陈述 + 常见误区/反面案例
- 字数控制：50-100字/框
- 出现位置：每个知识点后、模块过渡处、重要原理揭示时

### 2.4 警告框的标准格式

**文档2中的警告框示例：**
```

```

**格式规范：**
- 标记符号：⚠️ + "**常见踩坑**"或"**常见误区**"
- 内容结构：常见错误做法 + 正确做法 + 原因
- 功能定位：前置阻断错误认知

## 三、教学设计核心方法论

### 3.1 场景卡机制（课程主线贯穿）

**核心设计思想：**
用真实任务贯穿全程，避免练习孤立化。

**场景卡标准格式（文档1）：**
| 项目 | 你的填写 |
|------|---------|
| 这门课/这个流程叫什么 | |
| 讲给谁听 | |
| 学员现在的状态 | |
| 最大的困扰 | |
| 期待的改变 | |

**场景卡在学员手册中的变体（表单0.2）：**
| 场景卡 | 你的填写 |
|--------|---------|
| 我的岗位/角色 | |
| 我选定的任务名称 | |
| 这个任务通常怎么做 | |
| 目前最让我头疼的地方 | |
| 如果AI能帮上忙，我最希望改善什么 | |
| 最终产出是什么形式 | |

**设计逻辑：**
1. 课程开始时选定一个真实任务
2. 所有练习都围绕这个任务展开
3. 产出是这个任务的完整解决方案
4. 避免"做了七八个不相关的小练习"

### 3.2 懂/会/信教学目标体系

**学员手册中体现的三层目标：**
```
习惯1：主权定律
├── 懂：识别两种使用状态的本质差异
├── 会：掌握开口之前的主权三问
└── 信：建立主权思维而非依赖思维
```

**文档2中对"懂/会/信"的隐性应用：**
- 懂：理解专家语言vs学员语言的区别
- 会：能够完成改写练习
- 信：相信"先画面再术语"比"直接讲术语"更有效

### 3.3 学员需求三维分析

**文档2模块二的三维框架：**

| 需求类型 | 定义 | 教学内容对应 |
|---------|------|------------|
| 岗位需求 | 学员上岗后必须会的内容 | 必须讲透+现场演示 |
| 心理需求 | 学员担心、害怕的东西 | 额外补充（开场说明/消除顾虑） |
| 经验基础 | 学员已经会的东西 | 用来做类比/挂靠新知识 |

**完整示例的教学设计逻辑（文档2）：**
```
第一步：列出岗位需求 → 筛选出"必须讲透"的内容
第二步：识别心理需求 → 补充"额外要说的"内容
第三步：找到经验基础 → 设计"可以用来类比"的内容
↓
产出：学员分析表（决定模块详略）
```

### 3.4 产出链路设计

**文档1的两天产出链路：**
```
场景卡 → 学员分析表 → 模块框架图 → 案例化知识点
    ↓
第一天结束，产出汇总
    ↓
互动设计方案 → 课堂检验清单 → 30秒开场稿 → 完整教学方案+迷你授课
```

**文档5（产品经理12问）的产出链路：**
```
第一章产出：工作产品描述单 → 作为第二章输入
第二章产出：品效目标陈述 → 驱动后续所有模块
第三章产出：核心用户画像+洞见句 → 驱动第四章产品设计
第四章产出：产品设计四件套 → 第五章商业设计输入
第五章产出：商业设计三件套 → 第六章传播设计输入
第六章产出：全链路品效方案路演
```

**设计原则：**
- 前一环节产出 = 后一环节输入
- 缺一块，链路断一截
- 最终产出是"完整可直接使用的方案"

### 3.5 知识框架图标准格式

**文档6各章结尾的知识框架图：**
```
习惯 X：[名称]
│
├── [一级要素]
│   ├── [二级要素A]
│   └── [二级要素B]
│
└── [一级要素]
    ├── [二级要素]
    └── [二级要素]
```

**特征：**
- 树状层级结构
- 末尾无句点（保持简洁）
- 配合行为承诺表使用

### 3.6 行为承诺机制

**标准格式（文档6各章结尾）：**
```
从今天起，我承诺[具体行动]。

我将从这个任务开始实践：________________

签名：________________　日期：________________
```

**设计目的：**
- 从"知道"到"做到"的最后一公里
-书面承诺比口头承诺更有效
- 关联场景卡，确保可执行性

### 4.3 判断卡的标准格式（文档3）

**正面：问题类型定义**
```
#### 【类型名称】[一句话定义]

**举例：** [2-3个例子]

**特征：** [核心特征描述]
```

**背面：流程判断图**
```
这个问题是哪种类型？
            │
            ▼
[决策节点1]
      是 ↙     ↘ 否
      ▼              ▼
  [类型A]         继续问
                    │
                    ▼
         [决策节点2]
```

### 4.4 精准委托三要素框架（文档6第四章）

**三要素结构：**
| 要素 | 定义 | 回答问题 |
|------|------|---------|
| 背景(Context) | 任务发生的具体情境 | 谁/什么情况/什么限制 |
| 期望结果(Outcome) | 最终想要的产出形式 | 什么形式/多长/给谁/怎么用 |
| 质量标准(Standard) | 怎么判断是好的 | 必须有什么/必须避免什么/对方能做什么 |

**口诀：背景说清楚，结果说具体，标准说可验证**

## 八、教学文档设计的核心原则

### 8.1 内容组织原则

1. **从为什么到怎么做**：先揭示问题/误区，再给出方法
2. **先画面再术语**：任何知识点先用形象化方式建立理解
3. **用产出驱动学习**：每个模块都有可填写的产出物
4. **链路式设计**：前产出驱动后产出，缺一不可

### 8.2 格式设计原则

1. **分级清晰**：不同重要度的内容用不同的标题层级
2. **标记统一**：同类内容使用统一的标记符号
3. **填写区明确**：用表格/空行/下划线标注填写区域
4. **说明与内容分离**：填写说明用框框起，不干扰填写区域

### 8.3 练习设计原则

1. **三级难度递进**：基础→应用→拓展
2. **真实任务代入**：所有练习服务于场景卡
3. **参考答案配套**：主观题提供判断维度/参考答案
4. **讲师操作指引**：复杂练习配备引导流程

### 8.4 工具表单设计原则

1. **目的明确**：每张表单解决一个具体问题
2. **可独立使用**：单张表单可单独填写
3. **可迭代复用**：模板卡可反复使用
4. **质量可检验**：有明确的质量判定标准
