# 跨部门协作剧本杀完整创作 · 课程设计文档（RPD）

## 一、课程定位

### 课程名称（待定）

主标题候选：

- 《黑锅归谁》
- 《谁在挡路》
- 《项目出事了，你是哪个角色》

副标题方向：用剧本杀机制，把跨部门协作中最难讲清楚的事讲清楚

### 核心主张（一句话定位）

跨部门协作里最难教的东西，不是知识，是「感受」——感受到被踢皮球的无力、感受到背锅的委屈、感受到推进不动的焦虑。这门课不讲理论，用剧本杀让学员亲身经历一次跨部门协作的完整过程，然后在复盘中真正理解卡壳的根因，以及每个角色本来可以做什么。

### 与市面同类课的关键差异

| 维度 | 市面主流体验类课 | 本课 |
| :-- | :-- | :-- |
| 常见形式 | 沙盘、角色扮演、小组讨论 | 剧本杀：有完整故事、有隐藏信息、有角色目标 |
| 学员状态 | 知道自己在\"练习\"，行为偏表演 | 真的在追线索、博弈、推理，情绪真实 |
| 复盘价值 | 讨论的是\"应该怎么做\" | 复盘自己在游戏中「实际做了什么」，对应真实行为模式 |
| 迁移效果 | 听着有感触，难以记住 | 记住的是\"我在游戏里就这样搞砸了\" |
| 讲师负担 | 依赖讲师个人功力才能带动 | 剧本自带冲突动力，内容驱动，讲师做复盘引导即可 |

## 二、目标学员分析

### 主要学员画像

需要横向拉资源、推项目，但没有直线汇报关系的人，且已经在「跨部门协作课」场景里接受过基础训练，希望通过深度实践内化能力的群体：

- 中层管理者与项目负责人（推过事、卡过壁、没系统反思过）
- HRBP、运营、市场岗（天然的多方协调者，长期处于夹心层）
- 业务 PM、产品经理（项目推进主责，但资源都不在自己手里）
- 已上过「跨部门协作认知类课」的学员，需要一个深度体验场景巩固认知


### 学员认知起点

他们通常已经知道的：

- 跨部门协作需要对齐利益
- 推进要靠机制不靠口头承诺
- 对方也有自己的 KPI 和优先级压力

他们通常还没体验过的：

- 真正处于某个特定角色的「视角局限」是什么感觉
- 自己的无意识行为模式（比如习惯性踢球、防御性归因）是如何伤害推进的
- 信息不对称是如何让整个团队系统性失败的
- 「我当时明明是对的」和「事情最终还是没推动」可以同时为真


### 学员真实痛点

**体验层：做了但不知道为什么做**

- 上了认知课，懂了道理，但回到工作中还是老样子
- 以为自己能做到，真到冲突场景就原形毕露
- 缺一个「安全犯错」的练习场，让行为模式浮出水面

**觉察层：不知道自己的盲区是什么**

- 以为自己很好沟通，但同事觉得你难配合
- 以为自己在帮大局，但别人觉得你在甩锅
- 不知道自己在高压场景下会作出哪种本能反应

**迁移层：知道原则但不会应用**

- 上课能说出「要用利益逻辑」，但真实博弈里不会用
- 听过「推进机制」，但开完会还是不落责任
- 案例听懂了，但没有和自己的行为模式真正挂钩

## 三、业务问题诊断

### 表层问题（学员自己说的）

- "学了很多跨部门沟通的方法，但实际效果很有限"
- "理论上都明白，关键时刻就是做不到"
- "我们公司情况特殊，书上那套不适用"
- "培训做完了，行为没变化"


### 深层问题（真正卡住的根因）

**根因一：认知和行为之间有一堵「压力墙」**

知道道理不等于高压下能做到。大脑在威胁状态（被否定、被推责、被忽视）下会回到本能模式——要么攻击，要么退缩，要么合理化自己的行为。没有经历过在「假装安全但真实激活」的场景里练过，就无法建立新的行为路径。

**根因二：学员不知道自己的盲区在哪**

你看不到自己的盲区，因为它就是盲区。认知课能告诉你「别人怎么看这件事」，但无法让你「感受到别人是怎么看你的」。剧本杀机制让每个角色的行为对其他人可见，复盘时可以做到「你以为你在做什么 vs 其他人眼中你做了什么」的精确对比。

**根因三：信息不对称是真实世界的基本设定，但课堂从不模拟它**

绝大多数跨部门协作失败，根因之一是每个部门都只掌握局部信息，基于局部信息做了「局部最优」的决策，最终导致系统失败。常规培训里所有人看同一个案例，信息是对称的，永远无法复现这个问题。剧本杀天然解决这个问题：每个角色有自己的信息包，不能对其他角色完整公开。

**根因四：「复盘」价值没被充分挖掘**

复盘说的是「别人的事」，反思不了自己。剧本杀结束后的复盘不同——每个人在游戏里做了真实的判断和动作，复盘是对「自己行为」的反思，不是对案例的分析，学习效果本质不同。

### 高频应用场景（剧本设计的卡点还原锚点）

**场景 A：跨部门项目出问题，谁背锅的争议**
项目延期，各部门都认为自己没有问题，责任在别人那里。关键信息分布在几个部门手里，没有人拿到全局视角。

**场景 B：资源争夺，优先级冲突**
同一批资源被三个部门申请，核心资源方（IT/法务/财务）要选择配合谁。每个申请方都觉得自己的事最紧急、最重要。

**场景 C：一个决定必须多方拍板，但每个人都在等别人先表态**
典型的「会而不决」局面。每个人都不愿意第一个表态，因为表态意味着承担执行风险。博弈结构下信息窝藏，导致决策瘫痪。

**场景 D：历史恩怨影响当前合作**
两个部门有过旧账，现在新项目上线，双方都带着防备博弈，表面配合，实际上都在埋雷。

> 注：以上场景将以「同一个公司背景、同一套角色体系」的剧本呈现，学员在体验过程中会遇到多个场景交织，而非单一线性推进。

## 四、学习目标

### 总目标

学完这门课（体验 + 复盘），学员能够：

- 真实感受到「视角局限」是如何导致系统失败的，而不只是知道这个概念
- 识别出自己在高压博弈场景下的本能反应模式（攻击型/退缩型/合理化型）
- 用真实行为数据做复盘，找到自己在跨部门协作中的具体改善点
- 对「信息不对称」有感性认识，未来在真实协作中会主动构建信息共享机制


### 分层目标

**认知目标（Know）**

- 理解剧本杀机制如何复现职场跨部门协作的核心结构：角色利益冲突、信息不对称、优先级博弈
- 能说出自己在游戏中「本来想做什么 vs 实际做了什么 vs 造成了什么后果」
- 理解信息不对称在真实项目中如何系统性地制造失败

**技能目标（Do）**

- 能在复盘中准确识别自己的行为模式（不是泛泛而谈，而是对应游戏中的具体动作）
- 能用「利益地图视角」还原游戏中每个角色的真实诉求
- 能从复盘洞察中，提炼出一个对自己当前真实工作直接可用的行动改变

**迁移目标（Apply）**

- 把游戏中发现的自己的行为盲区，对应到当前手头一个真实的跨部门协作项目上
- 制定一个基于「行为模式自知」的个人协作改善计划（而不是泛化的「我要更好地沟通」）

## 五、课程逻辑主线

**叙事弧线（总体推进逻辑）**

本课以「沉浸体验 → 认知激活 → 行为复盘 → 模式识别 → 真实迁移」为主线，先让学员在安全环境里真实犯错，再用结构化复盘把错误转化为洞察，最后把洞察锚定到自己的真实工作情境。

**主线骨架**

```
第一步  破冰与角色代入
        学员进入角色，接收各自的信息包与目标设定
              ↓
第二步  剧本推进（博弈发生）
        信息流通、谈判、决策、冲突，真实行为浮现
              ↓
第三步  剧情揭底
        全局信息公开，每个角色看到其他角色的完整视角
              ↓
第四步  结构化复盘（核心学习时刻）
        「我以为自己做了什么 vs 其他人看到我做了什么 vs 实际结果是什么」
              ↓
第五步  模式提炼
        从个人行为到共性规律：跨部门协作失败的几种系统性机制
              ↓
第六步  真实迁移
        每人对应自己当前手头的真实场景，提炼一个具体的行动改变
```

## 六、课程模块架构

### 模块一：世界观建立与规则说明

**这个模块解决什么**

学员进来时的状态：把剧本杀当成游戏或娱乐，没有意识到这是一个「行为观察场」。

模块目标：让学员明白这门课的学习合约——游戏是真实的练习，复盘是真正的学习，两者缺一不可。

**核心内容方向**

- 为什么这门课用剧本杀形式：认知课能改变想法，体验课改变行为模式，缺的那块是「在真实情绪激活状态下的练习」
- 课程的学习合约：游戏中请认真博弈，不要表演「好学员」；复盘中请诚实，说你真正做了什么，不是你觉得应该做什么
- 剧本杀在这里的功能结构说明：角色目标（每人有自己的利益）、信息包（不对称分布）、推进机制（有时间节点和触发事件）
- 安全边界设定：这里允许犯错，游戏里的「坏行为」不会被评判，但复盘里需要诚实反思
- 简版规则说明：如何使用信息卡、如何触发事件、如何记录自己的决策路径

**学员离开时的状态**

清楚地知道「我在这里是为了发现自己的行为模式，不是为了赢」，同时足够期待接下来的游戏体验

### 模块二：角色代入与背景浸入

**这个模块解决什么**

学员进来时的状态：没有对角色的真实认同感，容易「演」而不是「做」。

模块目标：让学员在进入主游戏前，真正代入角色视角，有足够的动机去追求自己角色的目标。

**核心内容方向**

- 公司背景发布：剧本的世界观设定（虚构公司「远景科技」面临关键项目「猎鹰计划」的推进危机）
- 角色分配：每人领取自己的角色档案包（见附录），包含：
    - 角色身份：部门、职位、汇报关系
    - 公开信息：所有人都知道的关于你的信息
    - 私密信息：只有你知道的背景、历史、诉求
    - 角色目标：你这个角色在这次项目中最想达成的结果
    - 可用资源：你手里有什么筹码，可以用来交换或施加影响
    - 关系背景：你与其他角色的历史关系（可能有合作记录、也可能有历史嫌隙）
- 独立阅读时间（15分钟）：学员单独阅读，不允许与其他人交流，充分进入角色视角
- 角色确认：讲师逐一简短确认每个学员是否清楚自己的目标和信息，不需要公开，只是确保没有遗漏关键信息

**工具**

角色档案包（见附录一）：六个标准角色，适配6～12人的团队规模（可拆分或合并角色）

**学员离开时的状态**

知道自己要的是什么，知道自己有什么，知道自己面对哪些障碍——真实的角色动机驱动接下来的行为

### 模块三：剧本推进（主游戏阶段）

**这个模块解决什么**

学员进来时的状态：有了角色视角，但真实的博弈、冲突、信息操控还没有发生。

模块目标：在有限时间内，让学员真实经历跨部门协作中最典型的几个冲突节点，让真实行为模式自然浮现。

**核心内容方向**

游戏分三轮推进，每轮对应一个核心冲突节点：

**第一轮：资源申请会议（约30分钟）**

触发场景：猎鹰计划启动，三个业务部门同时申请IT资源支持，IT部门只有能力支持其中两个。各方需要在会议上「说服」IT部门优先支持自己。

核心博弈：谁的需求更有理由被优先响应？各方如何包装自己的需求？信息是否被完整披露？

真实行为观察点：学员是否使用了利益对齐逻辑？还是用权力压制？是否有人选择结盟？是否有信息被策略性隐藏？

**第二轮：危机处理（约25分钟）**

触发场景：猎鹰计划在执行中出现了一个关键问题，时间节点压力极大，需要某个部门做出一个「会增加自己工作量且有风险」的决定。同时，关于「谁该为前期问题负责」的争议开始浮现。

核心博弈：承担还是推脱？信息共享还是信息保护？利益共同体还是各自为战？

真实行为观察点：在压力下学员的本能反应是什么？有没有人选择主动牺牲换取长期信用？有没有人系统性地转移责任？

**第三轮：收尾与归因（约20分钟）**

触发场景：项目阶段性结束（结果可能是成功或失败，由游戏进程决定），需要向虚构的「高层」汇报。各部门需要在汇报前对齐口径，同时各自的隐藏目标也进入最终收割阶段。

核心博弈：如何在对外口径中保护自己？如何处理团队内部的责任分配？

真实行为观察点：「我们」和「我」的边界在这里最清晰地浮现——学员是在维护集体叙事还是在优化个人叙事？

**游戏进行中的讲师角色**

讲师不参与博弈，但承担三个功能：

- 触发事件发布（在合适时机推送新的信息卡，制造压力节点）
- 时间管理（每轮给出倒计时提示，增加决策压力）
- 行为记录（不打断游戏，在旁观察并记录关键行为节点，用于复盘引导）

**工具**

- 信息触发卡（见附录二）：讲师在合适时机向特定角色或所有人发布的新信息，共18张
- 行为观察记录表（讲师用，见附录三）：按角色记录关键决策动作，供复盘引导使用

**学员离开时的状态**

有了真实的情绪记忆——某个时刻被拒绝的感受、做了一个决定后的成就感或不安、被其他角色「意外」对待的惊讶。这些情绪记忆是复盘材料的原材料。

### 模块四：剧情揭底与视角重建

**这个模块解决什么**

学员进来时的状态：每个人只有自己的视角，无法理解为什么其他角色会那样行动。

模块目标：公开全局信息，让每个学员第一次看到「完整的图景」，引发自发的「如果我早知道……」反思。

**核心内容方向**

- 角色信息全公开：每个角色逐一公开自己的私密信息和隐藏目标（可以是自我公开，也可以是讲师引导揭露）
- 关键时刻复现：选择游戏中2～3个关键决策节点，让每个相关角色说出「我当时知道什么、我当时在想什么、我当时决定了什么」
- 信息地图重建：讲师在白板上画出「信息流动图」——哪些信息在游戏中真正流通了，哪些被锁住了，哪些被策略性地只传给了部分人
- 结果还原：如果信息是完全对称的，大家的决策会有什么不同？（这个问题不是指责，而是建立系统视角）

**工具**

信息流动图模板（见附录四）：可视化呈现信息的流动与阻断，讲师在白板实时绘制

**学员离开时的状态**

第一次完整看到「我以为这是对方的恶意，其实是信息不对称的必然结果」——这是从个人归因向系统归因的真正转变，也是整门课最高价值的时刻之一

### 模块五：结构化复盘（核心学习时刻）

**这个模块解决什么**

学员进来时的状态：有了体验，有了情绪，但还没有把体验转化成对自己行为模式的清晰认识。

模块目标：用结构化引导，让每个学员完成「我在这里的行为模式是什么」的真实认知，而不是泛泛的感想分享。

**核心内容方向**

复盘分三个层次推进：

**第一层：行为事实层（不评价，只描述）**

每位学员回答：

- 在游戏中，你做了哪三个让你印象最深的决定？
- 其中有没有一个，事后想来你觉得你应该做不同的选择？
- 有没有一个你在当时觉得是对的，现在信息全部公开了之后你还是觉得是对的？

**第二层：模式识别层（从行为到规律）**

讲师引导全组识别以下几种常见行为模式（不点名，用行为描述）：

- **信息窝藏型**：有信息但策略性不共享，因为觉得「分享会损害自己的筹码」
- **本能防御型**：一旦感受到被指责或被否定，立刻转向解释自己为什么没错
- **沉默等待型**：不表态，等别人先动，避免暴露自己的立场
- **合理化归因型**：把系统失败归因到某个人的问题，而不是结构问题
- **超级协调型**：试图让所有人都满意，结果没有人真正做出承诺

每个模式描述之后，请学员自己在心里识别：这个模式有没有在我身上出现？

**第三层：真实迁移层（从游戏到工作）**

引导问题：

- 这个你刚刚在游戏里发现的行为倾向，在你的真实工作中，最近有没有出现过类似的情况？
- 如果有，当时的后果是什么？
- 如果下次再遇到类似场景，你具体会做哪一件不一样的事？

**工具**

复盘三层引导卡（见附录五）：学员个人填写，非公开分享，只需要对自己诚实

**学员离开时的状态**

手里有一张写着「我发现了关于自己的一件真实的事」的卡片，以及「下次我会具体怎么做」的行动意图

### 模块六：共性规律提炼与行动落地

**这个模块解决什么**

学员进来时的状态：有了个体层面的洞察，但没有建立「这个规律可以迁移到其他情境」的连接。

模块目标：从个体体验中提炼跨部门协作失败的几条共性系统机制，让学员用「系统视角」而非「人的问题」来看待未来的协作卡壳。

**核心内容方向**

- 三条核心规律的讲师总结（从游戏现象提炼，非强行灌输）：

**规律一：信息不对称是卡壳的结构性原因，不是态度问题**

游戏里没有一个「坏人」，但最终几乎所有人都做出了「在他的视角下理性，但在全局视角下破坏性」的决策。这在真实组织里天天发生，只是没有人把全局信息公开出来让大家看到。

**规律二：推进失败往往是「每个人都在保护自己」的集体后果**

没有人想搞砸，但所有人都在用策略性行为保护自己，最终没有人在推动事情。「好好配合」的前提不是道德，是让每个人都觉得「配合不会伤害自己」。

**规律三：高压场景下，人的本能反应往往精准地制造他最担心的后果**

怕被甩锅 → 开始甩锅
怕推进失败 → 开始混淆责任
怕被认为不配合 → 说了很多但没有承诺任何具体的事

- 行动落地：每位学员填写「一张纸计划」（见附录六）

**工具**

「一张纸计划」（见附录六）：三个问题，一张纸：

1. 我发现的关于自己的一个行为模式是什么？
2. 这个模式在我当前工作中，在哪个具体情境里最容易出现？
3. 接下来两周内，我会在那个情境里具体做哪一件不一样的事？

**学员离开时的状态**

不是「收获了很多」，而是「知道自己要改一件具体的事是什么」

## 八、教学策略设计

### 开场与引入原则

不解释「为什么要用剧本杀形式」，而是直接用「你上次推一个跨部门项目，有没有一刻你觉得明明是你对的，但事情还是卡住了」来激活学员的真实情绪记忆，再用这个记忆作为学习动机的入口。

### 游戏进行中的讲师原则

- 讲师的身份是「游戏主持人」，不是「老师」——在游戏阶段绝对不点评，不打断，不引导
- 游戏阶段的核心价值来自学员自发的行为，讲师干预会破坏这个价值
- 只有在「游戏规则层面」出现问题时才介入（比如有人不理解某张信息卡的意思）
- 使用行为观察表持续记录，这些记录是复盘引导的精确素材


### 复盘引导原则

- 永远从「行为事实」开始，而不是从「感受」或「观点」开始——「你做了什么」比「你觉得这件事怎么样」有更高的反思价值
- 不点名评价任何人的行为，而是描述行为模式，让学员自己识别
- 如果学员倾向于「这是游戏嘛，我现实不是这样的」，引导提问是：「这个反应本身（否认游戏与现实的关联）在你工作里有没有出现过？」
- 给每个人安全地「认领自己行为」的空间——用「哪些人有这个经历」而不是「你刚才就是这么做的」


### 评估设计

**过程性评估**

每轮结束时，每位学员用一句话记录「这一轮我做的最重要的一个决定」，交给讲师作为复盘材料。这不是打分，是为了让学员保持「有意识的观察者」的状态。

**结课任务（终结性评估）**

一周后，学员提交一个简短的「行为迁移日记」——描述在真实工作中，他们在某个跨部门协作场景里，尝试了在剧本杀复盘中发现的那个新的行为，结果如何，以及下一步想调整什么。

不需要完美，不需要成功。需要真实。

- 是否有真实案例可以脱敏后融入剧本背景，提升学员代入感？

**关于剧本设定**

## 二、第一层：规则层（2个文件）

### CLAUDE.md — 顶层规则文件

**格式：** Markdown，放在项目根目录
**作用：** 这是 Claude Code 进入项目时第一个读取的文件。它定义整个创作系统的身份、调度逻辑、文件规范和质量标准，是所有 Agent 行动的宪法。
**内容标准：**

```
必须包含的五个部分：

1. 项目身份定义
   - 这是什么项目、要创作什么、面向什么用途
   - 明确区分「剧本杀游戏内容」和「培训工具内容」两个身份

2. 创作顺序规则
   - 严格规定：世界观 → 角色总表 → 六个角色档案 → 三轮剧本 → 信息卡 → 复盘材料 → 讲师手册
   - 任何步骤必须等前置文件生成完毕才能启动
   - 禁止在角色档案未完成前创作信息卡

3. 文件命名与存放规范
   - 每类文件的命名格式、存放路径、编号规则

4. 一致性要求
   - 所有文件中角色名字、职位、关系描述必须引用 role-master.md
   - 所有事件时间线必须引用 timeline.md，不允许自行发明日期
   - 信息卡中的信息必须能在对应角色档案的私密信息中找到来源

5. 质量门控
   - 每个主要模块完成后，必须触发 reviewer agent 执行一致性检查
   - reviewer 通过后才能进入下一模块
```

**输出：** 不生成内容，只规范行为

### .claude/skills/murder-mystery/SKILL.md — Skill 主入口

**格式：** Markdown，遵循 Agent Skills 开放标准
**作用：** 用户在 Claude Code 里输入触发命令后，这个文件决定调用哪个 Agent、按什么顺序、传什么参数
**内容标准：**

```
必须包含：

1. Skill 基本信息
   - 名称：murder-mystery-collab
   - 描述：创作跨部门协作剧本杀完整剧本包
   - 触发命令：/create-mystery, /create-roles, /create-scripts, /create-cards, /export

2. 触发条件与参数
   - /create-mystery [主题] [人数]：全流程创建
   - /create-roles：只生成/重新生成角色档案
   - /create-scripts [round]：生成指定轮次剧本
   - /create-cards：生成所有信息触发卡
   - /export [type]：生成学员包或讲师包

3. Agent 调度逻辑
   - 每个命令对应的 Agent 调用顺序
   - 每个 Agent 的输入文件和输出文件
   - 断点续接逻辑：如果中间文件已存在，跳过该步骤

4. 上下文管理规则
   - 哪些文件是 always-load（每次都读）
   - 哪些文件是 on-demand（按需读取）
```

## 三、第二层：世界观层（4个文件）

### world/company-profile.md

**格式：** Markdown，结构化段落
**作用：** 是全套剧本的「世界宪法」，所有角色的背景、所有事件的发生，都必须与这里的设定兼容
**内容标准：**

```
必须覆盖：
- 公司名称、规模、行业、所在城市（具体，可信）
- 公司文化特征：是强执行文化还是共识文化？是KPI驱动还是OKR驱动？
- 组织结构：六个部门的汇报关系、与CEO的距离
- 历史背景：公司最近12个月的重要事件（影响各部门状态）
- 公司痛点：什么问题是全公司都知道的老大难（为剧本冲突提供合理性）

输出标准：
- 2000字以上
- 任何人读完后能立刻在脑海中描绘出这家公司的样子
- 不能有内部矛盾（比如说是500人公司但描述的文化像30人创业团队）
```


### world/project-background.md

**格式：** Markdown，含项目简介、目标、各部门职责、时间表
**作用：** 猎鹰计划是整个游戏冲突的核心载体，这个文件定义这个项目的「官方说法」——即所有人公开知道的信息
**内容标准：**

```
必须覆盖：
- 项目为什么启动（业务背景，要有说服力）
- 项目的成功标准是什么（清晰的指标）
- 每个部门在这个项目里的官方职责
- 项目的已知风险（为后续触发卡埋伏）
- 项目的时间节点（精确到周，是信息触发卡的时间依据）

写作要求：
- 用「项目启动说明书」的语气，像真实企业文件
- 不能包含任何私密信息（私密信息只在角色档案里）
- 模糊地带必须刻意留出来（这是冲突的来源）
```


### world/relationship-map.md

**格式：** Markdown + 文字描述关系图（因无法生成真图，用矩阵表格代替）
**作用：** 是所有角色关系历史的「单一事实来源」，所有角色档案中涉及的历史关系，都必须从这里引用，不能各自发明
**内容标准：**

```
必须覆盖：
- 6×6 关系矩阵：每对角色的关系性质（合作/中立/有嫌隙/未知）
- 每段有特殊背景的关系：发生过什么、什么时候、结果如何、各自的情绪残留
- 非正式关系网络：谁和谁私下有来往（不公开但影响博弈）

约束：
- 关系必须「不对称」：A觉得和B关系不错，B可能觉得一般
- 每段关系的历史必须具体（不能写「曾经合作过」，要写「2024年Q3，陈伟和王敏在数据安全项目上合作过三周，最终陈伟的团队加班完成了法务提出的最后一批修改要求，但没有人感谢他们」）
```


### world/timeline.md

**格式：** Markdown 时间线，按「周」为单位
**作用：** 游戏内所有事件的时间参照，确保信息触发卡、角色私密信息、剧本情节在时间上不冲突
**内容标准：**

```
游戏开始前（T-12周 至 T-1周）：
- 猎鹰计划提出、立项、各部门确认参与的节点
- 关键历史事件（影响关系背景的那些）

游戏当周（T0）：
- 第一轮开始的时间节点
- 各触发卡对应的时间点
- 项目真正的死线（外部约束）

格式要求：
- 每个时间点用「第X周/X月X日」标注
- 每个事件标注「谁知道/谁不知道」
```

## 四、第三层：角色层（7个文件）

### roles/role-master.md — 六角色总览表

**格式：** Markdown 表格 + 摘要段落
**作用：** Agent 在创作任何角色相关内容前必须先读这个文件，确保六个角色的核心设定不互相矛盾，筹码分配平衡
**内容标准：**

```
必须包含：
- 六个角色的一行摘要（姓名/部门/职位/核心诉求/隐藏动机 一览）
- 筹码平衡检查表：每个角色拥有什么筹码，是否有一个角色过强导致游戏失衡
- 信息分布检查表：关键信息分布在哪些角色手里，确保没有一个角色掌握太多或太少
- 冲突矩阵：哪两个角色之间有直接冲突，哪两个是潜在盟友
```


### roles/role-0X-[Name].md — 六个角色完整档案（×6）

**格式：** Markdown，分「公开版」和「私密版」两个区块，用明确的分隔标记区分
**作用：** 每个学员的「角色包」直接从这个文件提取。公开版所有人可见，私密版只发给对应学员
**每个角色档案必须包含的板块：**

```
【公开信息区块】
- 人物基本信息：姓名、年龄、职位、入职年限
- 在这家公司的公开形象（同事怎么看他）
- 在猎鹰计划中的官方职责（引用 project-background.md）
- 可观察到的工作风格（其他角色能看到的行为特征）

【私密信息区块】（只有该角色本人可见）
- 真实历史：影响他现在行为的过去经历（具体事件）
- 隐藏诉求：这次游戏他真正想达成的目标（可能和公开职责有出入）
- 知道的秘密：哪些信息只有他掌握，以及他是怎么得到这些信息的
- 筹码与弱点：他可以动用什么，以及什么是他不能暴露的
- 关系立场：对其他每个角色的真实态度（不是公开的礼貌，是内心评价）
- 行动建议：三个可选策略（合作路线/博弈路线/观望路线），让玩家有选择

【角色扮演指引】
- 这个角色的说话风格（举例：张建国说话会引用数字，喜欢说「从数据来看…」）
- 这个角色在压力下的本能反应
- 这个角色最容易露馅的时刻

【与复盘的连接】
- 这个角色最可能让玩家体验到的行为模式是哪一种
- 如果玩家扮演这个角色，复盘时最应该被问的一个问题
```

**字数标准：** 每个角色档案不少于 2500 字，私密区块不少于 1200 字

## 五、第四层：剧本内容层（5+4+1 个文件）

### scripts/round-00-intro.md — 主持人开场剧本

**格式：** 剧本格式（主持人台词 + 操作指示 + 时间标注）
**作用：** 讲师逐字可读的开场引导，把学员从「上培训课」的心理状态切换到「进入游戏」的心理状态
**内容标准：**

```
结构：
1. 进场引导（学员坐定后的第一句话 → 破冰问题 → 进入叙事）
2. 世界观交代（用3分钟讲清楚远景科技是什么公司，猎鹰计划是什么项目）
3. 角色分配仪式（发角色包的标准流程，怎么保持私密性）
4. 规则说明（信息卡怎么用、计时规则、边界设定）
5. 独立阅读时间（15分钟的引导语：告诉学员这15分钟做什么）
6. 开场问题（进入第一轮前的触发问题，让每个角色说一句话正式入戏）

格式要求：
- 主持人说的话用「引号」括起
- 操作动作用【方括号】标注
- 预计用时标注在每个段落旁边
- 总时长控制在 20-25 分钟
```


### scripts/round-01/02/03-[name].md — 三轮剧本（×3）

**格式：** 场景剧本格式，含「场景设定 + 触发事件 + 角色行动空间 + 讲师观察点 + 收尾节点」
**作用：** 是游戏的核心内容，规定每轮的冲突结构、触发节点、可能走向
**每轮剧本必须包含：**

```
一、场景设定（全员读，用来开场）
- 这一轮发生了什么情况（新的触发事件）
- 每个人当前的处境（基于上一轮结果）
- 这一轮必须达成什么结果才能进入下一轮

二、角色行动空间
- 每个角色这一轮可以做的事（不是固定台词，而是行动选项）
- 每个角色这一轮的独特压力点（让他有理由行动）
- 每个角色的「高价值信息」（如果披露，会改变局面）

三、讲师触发节点
- 在第X分钟发布哪张信息卡
- 触发条件：什么情况下主动介入，什么情况下让局面自然发展
- 如果局面太僵（没人行动）：备用激活指令
- 如果局面太乱（超出控制）：收束指令

四、预设走向树
- 可能结局A：某两方结盟，IT配合推进
- 可能结局B：多方僵持，项目面临延期
- 可能结局C：某个角色的隐藏信息被提前揭露，局面剧变
- 每种走向如何自然收尾，进入下一轮

五、这一轮的复盘素材
- 这一轮最可能出现的行为模式有哪些
- 讲师应该特别记录的2-3个关键行为节点
```

**字数标准：** 每轮剧本不少于 3000 字

### scripts/debrief-script.md — 揭底与复盘引导剧本

**格式：** 讲师话术库 + 引导流程图
**作用：** 这是整门课学习价值最集中的地方，也是最考验讲师能力的环节。这个文件把复盘变成可执行的标准流程
**内容标准：**

```
结构：
1. 揭底仪式（如何逐一公开角色私密信息，什么顺序，怎么营造「啊原来如此」的时刻）
2. 信息流动图绘制话术（讲师一边画一边说什么）
3. 三层复盘引导话术：
   - 行为事实层：开场提问 + 追问话术 + 沉默时的接话
   - 模式识别层：每种行为模式的描述语，不带评判的中性表达
   - 真实迁移层：「这在你工作里有没有」的引导方式
4. 应对难场景话术库：
   - 学员不愿意承认自己行为时
   - 学员过度自我批评时
   - 学员互相指责时（把个人冲突转向系统反思）
   - 学员认为「游戏和现实不一样」时
5. 收尾仪式（如何结束复盘，给学员一个清晰的心理出口）

格式要求：
- 讲师话术用「引号」
- 说明性文字用正常排版
- 关键话术标注「高价值」提示
```

## 六、第五层：信息卡层（4个文件）

**作用：** 是游戏进行时的核心动力机制，每张卡都是一次新的压力注入，迫使角色做出新的判断
**每张信息触发卡的标准模板：**

```

│ 发放时机：第X分钟 / 触发条件  │
├─────────────────────────────┤
│ 【信息内容】                  │
│ （学员看到的内容，语气要真实）  │
│                              │
│ 【来源形式】                  │
│ □邮件  □消息截图  □便条       │
│ □口头转达  □内部公告          │
├─────────────────────────────┤
│ 【讲师注释】（仅讲师可见）     │
│ 设计意图：这张卡要制造什么压力 │
│ 预期反应：角色可能的三种反应   │
│ 连带影响：影响哪个后续卡的时机 │
└─────────────────────────────┘
```

**质量标准：**

- 每张卡的信息必须有来源（可以在某个角色的私密信息或 timeline 里找到根据）
- 发给特定角色的卡，内容必须对其他角色保密且合理
- 18张卡的发布节奏必须均匀：每轮6张，不能前重后轻
- 不能有两张卡制造完全相同的博弈结构

## 七、第六层：讲师运营层（4个文件）

### facilitator/facilitator-handbook.md — 讲师完整操作手册

**格式：** Markdown，按时间顺序的操作说明书
**作用：** 让一个读过这份手册的陌生讲师，能够独立带出完整的游戏体验
**内容标准：**

```
必须覆盖：
1. 课前准备清单（材料、场地、印刷要求、时间安排）
2. 分钟级操作时间表（全程4-5小时，每15分钟讲师做什么）
3. 角色分配策略（如何根据学员特点分配角色，有无禁忌组合）
4. 信息卡管理（18张卡如何提前准备、按时发放、避免混淆）
5. 关键判断点（什么情况下提前结束一轮，什么情况下延长时间）
6. 意外情况处理（学员角色冲突变成真实人际冲突时如何介入）
7. 复盘阶段的节奏控制（多长时间是好的，怎么感知学员的状态）
```


### facilitator/observation-sheet.md — 行为观察记录表

**格式：** 可打印表格（Markdown 表格格式）
**作用：** 讲师在游戏进行中不能频繁打断，但需要记录关键行为作为复盘素材。这张表让记录动作最小化、观察精度最大化
**内容标准：**

```
表格结构：
- 行：6个角色
- 列：6个关键观察维度
  · 是否主动分享信息
  · 是否策略性隐瞒信息
  · 在压力下的本能反应（攻击/退缩/合理化）
  · 是否尝试利益交换
  · 是否寻求结盟
  · 关键决策节点的具体动作

设计要求：
- 每格只需要打勾或写2-3个字，不能要求讲师在游戏中写长句
- 预留「突发行为」记录栏
```


### facilitator/debrief-guide.md — 复盘引导话术库

**格式：** Q\&A 结构，按情境分类
**作用：** 复盘时的讲师工具书，按「学员说了什么、讲师接什么」的格式组织，覆盖所有高频情境
**内容标准：**

```
必须覆盖的情境类别：
- 学员主动深度反思时（如何扩大、深化）
- 学员浅层应付时（如何激活）
- 学员防御性回应时（如何绕过防御）
- 全组沉默时（如何打破）
- 两人互相指责时（如何重定向到系统）
- 有人过度主导讨论时（如何平衡）
- 时间不够时（如何压缩但不损失核心价值）

格式：
学员说/做：「…」
讲师接：「…」
避免说：「…」（踩坑提示）
```


### facilitator/faq.md

**格式：** Q\&A Markdown
**作用：** 把游戏设计意图和理论依据转化成简洁问答，供讲师在被学员质疑时有依据地回应
**内容标准：**

```
必须回答的问题：
- 「为什么不直接说案例，非要用游戏的形式？」
- 「游戏毕竟是游戏，我真实工作里不会这样」
- 「某个角色是不是太强/太弱了，游戏不公平」
- 「我觉得自己表现还好啊，其实是角色设定导致的」
- 「这个游戏对某个部门不公平」
- 「可以不复盘、直接结束吗？」
```

# 有哪些你觉得重要的？就是没有太多提到的，给我补充内容，我最后一次问你就是后面我就直接把你给我的所有东西拿去给Claude Code帮我去做产出了。

这是个好问题。我回头看了一遍我给你规划的东西，发现有几个地方我只定义了「要有这个文件」，但没有说清楚里面真正难的部分是什么。Claude Code 拿到我给的规划直接去做，大概率会在这几个地方产出质量不够高，或者产出了你用不了的东西。

我分三类补充：**设计逻辑层（为什么这么做）、内容难点层（最容易做差的地方）、运营细节层（只有真正带过才知道要准备的东西）**。

## 关于「信息不对称」的设计精度

我在 RPD 里说了信息要不对称，但没有说清楚「不对称的粒度怎么控制」。这是整个剧本杀成败的核心机制，Claude Code 如果没有具体约束，很容易把私密信息做成「各自藏着掖着但互不影响」的状态，那游戏就废了。

真正有张力的信息不对称，需要满足一个条件：**A 的私密信息，恰好是 B 做出正确决策所需要的信息**。也就是说，每条私密信息都应该有一个「如果这个信息被 B 知道，B 的行为会发生 180 度改变」的对应角色。

给 Claude Code 的具体约束应该是：每个角色的私密信息列表里，每一条必须标注「如果这条信息被谁知道，会改变什么」。如果一条私密信息对所有其他角色的行为都没有影响，它就不该出现在剧本里。这个约束直接决定信息卡的设计质量。

## 关于「角色筹码平衡」的隐患

你的六个角色里，IT（陈伟）是筹码最重的——所有人都需要他。这在现实里确实如此，但在游戏里会造成一个结构性问题：如果陈伟的玩家是一个高控制欲的人，他可以让整个游戏完全按他的节奏走；如果陈伟的玩家是一个不擅长社交博弈的人，他会完全不知道怎么用自己的筹码，游戏会陷入僵局。

需要给 Claude Code 补充一个约束：**陈伟的角色档案里必须有一个「致命弱点」，且这个弱点至少对两个其他角色可见**。比如：他的团队有人随时可能离职（HR 知道），他自己对 CEO 也有一个未完成的承诺（财务隐约知道）。这样他的强势筹码就被软化了，游戏不会被他一人垄断。

类似的逻辑，HR（刘芳）目前是筹码最弱的角色——她有一份报告但不知道该不该发。需要给她补充一个「主动推进游戏」的理由，否则她会全程只是观察者，没有动力介入冲突，学员扮演这个角色会无聊。

## 关于三轮剧本的「压力递增」设计

我提到了「节奏前紧后松」，但说反了——应该是**前松后紧**，压力递增。第一轮是博弈热身，大家还在试探；第二轮是真正的压力场，情绪开始激活；第三轮是最后博弈，隐藏动机全部浮出水面。Claude Code 需要一个明确的压力参数，否则三轮会做出相似的张力密度。

给 Claude Code 的约束是：

- 第一轮：每个角色最多暴露 30% 的私密信息，博弈以「测试对方底线」为主
- 第二轮：有 1-2 张信息卡会强制暴露某角色的一个私密信息（不是当事人主动披露，是被动暴露），这是情绪最激活的时刻
- 第三轮：所有角色必须做出至少一个「不可撤回的公开承诺」，为揭底阶段的反差埋下伏笔


## 关于「扩展至12人」的机制

我提到角色可拆分到 12 人，但没有说怎么拆。如果 Claude Code 按字面意思去做，可能会创造 12 个独立角色，那整个剧本的信息结构就垮掉了。

正确的拆分逻辑是：同一个部门分成「负责人」和「执行层」两个角色，他们有共同的部门利益，但有不同的个人立场。比如陈伟是 IT 负责人，他追求「保护团队不被随意征用」；他手下的工程师小李追求「这个项目能不能帮我在简历上加分，还是只是加班」。两人在同一桌上，会产生「上下级在跨部门协作里的利益分裂」这条新冲突线。需要在 role-master.md 里明确说明哪六个角色可以拆分、拆分的利益分裂点是什么。

## 关于复盘阶段的「行为模式命名」

这是我认为最容易被 Claude Code 做成泛泛而谈的地方。我在 RPD 里列了五种行为模式（信息窝藏型、本能防御型等），但这五个名字太「培训课」了，学员听到会立刻进入「被分析」的心理防御状态。

更好的做法是**用行为描述代替标签**。不说「你是信息窝藏型」，而是说「有没有人在某个时刻，手里有一条信息，你当时判断『告诉他们对我不利』，所以选择没说？」这样学员识别的是行为，不是身份，防御心理小很多。

需要在 debrief-guide.md 里明确要求：五种行为模式，每一种都有「标签版」（讲师内部参考）和「行为描述版」（对学员说的版本），Claude Code 必须两个都写，且对学员版必须是第一人称提问句，不能是第三人称描述句。

## 关于「一张纸行动计划」的问题设计

这是课程最后的落地动作，也是最容易被学员糊弄过去的环节。「我要加强跨部门沟通」这种答案完全没有用，但如果问题本身不够具体，学员就会写这种东西。

三个问题需要被强约束：

- 第一题必须引导到**具体行为**，不能是态度或认知。参考措辞：「你在游戏里，在哪一个具体时刻，做了一个让你现在后悔的决定？那个决定是什么？」
- 第二题必须引导到**具体情境**，不能是泛化场景。参考措辞：「你现在手上有没有一个正在推进的跨部门事项？它叫什么名字，下一个关键节点是什么时候？」
- 第三题必须引导到**具体的下一步行动**，时间范围控制在两周内。参考措辞：「在那个事项的下一个节点之前，你会做哪一件和今天游戏里不一样的事？只说一件，越具体越好。」

这三个问题的逻辑是：先锚定记忆（游戏里的具体时刻）→ 再锚定现实（真实的手头项目）→ 最后锚定行动（一件具体的事）。这个顺序不能颠倒。

## 关于「游戏可能失控」的场景预案

我在 facilitator-handbook.md 里提到了意外情况处理，但没有具体说哪些情况。有三个场景在真实培训里会发生，需要给讲师具体的应对动作：

**场景一：某个学员完全不入戏，全程用「游戏角度」而不是「角色角度」行动**。他会说「我知道这是游戏，所以我就随便玩玩」。这个人其实是防御心最重的人，他用「游戏性」来保护自己不被看见。讲师的应对不是催他入戏，而是在复盘时单独对他说：「你刚才说『随便玩玩』，那在你真实工作里，有没有一种场合，你也会用这种方式？」

**场景二：两个学员的角色冲突变成了真实人际冲突**。这在有历史矛盾的团队里几率不低。应对原则是：不要在游戏进行中打断，但在揭底之前先做一个「降温动作」，说「接下来大家先退出角色，你们现在说的是角色，不是你们自己」，然后再继续揭底。

**场景三：游戏走向了一个「皆大欢喜」的假和谐结局**，所有人配合得太好，没有冲突，游戏没有张力。这说明这个团队的心理安全感不足，或者这批学员的关系太好。讲师需要在第二轮开始时注入一张「强制冲突卡」——建议在信息触发卡里预备两张备用冲突卡，只在这个情况下发放。

## 最后一个补充：AI 生成后必须做的人工检查点

这个最重要，但我之前完全没提。Claude Code 按照我们的规划跑完之后，会有几个地方是 AI 系统性做不好的，必须有人工介入：

**第一个检查点：角色私密信息的「可披露性」**。AI 容易把私密信息写得太黑暗（背叛、操控）或太平淡（只是有一点点压力）。你需要确认每条私密信息都在「有点不舒服但不会让人真的排斥角色」的区间里——因为学员要代入这个角色，如果私密信息让他觉得这个角色太坏，他会不自在。

**第二个检查点：信息卡的「语气真实性」**。AI 写的邮件截图和消息记录通常太正式、太干净，不像真实企业通讯。需要检查每张以「邮件」或「消息截图」形式出现的信息卡，加入真实人类通讯的特征：有错别字、有语气词、有随机的非正式内容。

**第三个检查点：复盘话术的「去培训感」**。AI 写的话术天然带有培训课的腔调，说出来学员会立刻感觉「这是设计好的引导」，防御心就上来了。需要有人把复盘话术里所有「我们发现……」「这个研究表明……」的句式全部改掉，换成问句和叙事。

这三个检查点，没有 AI 能替你做。把这三条加进 CLAUDE.md 的末尾，让 Claude Code 在最终输出时主动提示你「以下三个地方需要人工审查」，并列出对应的文件和具体段落位置。
