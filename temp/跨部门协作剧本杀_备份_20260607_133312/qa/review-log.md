## 一、QA 审阅原则

### 1.1 审阅维度

QA 审阅工作从八个维度对项目进行逐项核验：

1. **事实一致性**：所有数字、姓名、时间、职位与 world/ 一致
2. **角色一致性**：6 角色行为合理，没有坏人
3. **机制一致性**：3 轮次、18 信息卡流程与 scripts/ 一致
4. **培训一致性**：复盘三层觉察与 debrief-script 一致
5. **格式一致性**：所有 markdown 文件格式统一
6. **敏感词**：避免所有可能触发 API 敏感词的内容
7. **专业性**：避免甩术语装逼
8. **可读性**：避免空话、套话

### 1.2 审阅级别

- **L1（严重）**：影响游戏正常运行，必须修复
- **L2（重要）**：影响培训质量，需要修复
- **L3（一般）**：影响阅读体验，建议修复
- **L4（建议）**：可优化项，不强制

### 1.3 审阅流程

1. **初稿完成** → QA 第一次审阅
2. **初稿修改** → QA 第二次审阅
3. **终稿** → QA 终稿审阅
4. **投产** → QA 验收

### 1.4 审阅方法

- **双盲交叉审阅**：每个文件至少由 2 个 QA 子智能体独立审阅
- **源头文件校验**：所有事实性内容必须与 world/company-profile.md、world/project-background.md 源头对齐
- **敏感词扫描**：使用关键词列表对所有文件进行扫描，确保无「隐藏」「不可告人」「策略性」「嫁祸」「攻击」「防御」「报复」「甩锅」「窝藏」「博弈」「操控」「致命弱点」「信息窝藏」「策略性隐瞒」等表述
- **培训目标回归**：所有内容必须服务于「让参与者在差异化信息下觉察自己的反应模式」这一核心目标
