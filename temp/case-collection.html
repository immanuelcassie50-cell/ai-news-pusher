案例索引

课程中使用的核心案例及对应章节

1 PART 1 认知层

  • 八个月丢单：那个从没露面的信息安全负责人

    商务经理、预算负责人、IT经理都表态后，合同评审会上信息安全负责人一句"数据出境方案没评估过"让项目重新回到起点。

    → 第一章：复杂决策链里没有"决策人"

  • 业务负责人以为自己能拍板

    十年销售经验者签单后，采购总监坦言"你早该来找我"——业务部门一直表现得像最终拍板人，实际只是"技术上认可"这一环。

    → 第一章：复杂决策链里没有"决策人"

  • 愿意见你和能拦住你不是同一批人

    销售内部那些跟你聊得投缘、愿意透露内部信息的人，往往是因为手里权力不大而有闲功夫；真正握着否决权的人通常忙得没空跟供应商建立私交。

    → 第二章：你交的朋友，是否决权已经过期的那批人

  • CRM名单上的假地图

    联系人名单只覆盖了愿意主动露面的那部分人，真实的财务、法务、集团采购部门从未出现在会议邀请名单里。

    → 第三章：你手里的联系人名单，是一张假地图

  • 角落里最沉默的人

    会议室里那个没怎么说话的中年人，只在方案讲到数据接口时问了一句技术细节。会后被认为"打酱油"，三周后正是他卡住了数据接口安全评估。

    → 第五章：找到那个不承认自己有权力的人

  • 预算批了，流程还没完

    客户业务部门明确表态预算已批，书面确认也有了。两个月后才知道"预算已批"只是业务部门预算池有这笔钱，真正拨付还需走财务付款审批和集团比价流程。

    → 第六章：预算审批不是一道关卡，是一条河

  • 技术评审前的那句话

    资深解决方案顾问在进技术评估会前，总会先问："如果这个方案出了问题，是您的团队来处理，还是要走供应商的应急响应？"——帮评审人想清楚风险责任划分。

    → 第七章：技术评估节点否决的不是方案，是风险

  • 同一份方案，讲给不同的人听

    一份从头到尾只讲功能优势和技术领先性的方案，财务负责人从头到尾没提问，会后反馈"没听懂跟我们有什么关系"——讲错对象，再好的方案也白讲。

    → 第八章：同一件事，对不同的人要讲不同的故事

  • 催出来的额外审查

    项目进入法务评审阶段，销售因担心节奏拖太久连续三天打电话催问，法务反而在评审意见里加了"建议进一步核实供应商资质"，流程多绕了一圈。

    → 第九章：该等的时候别推，该推的时候别等

  • "整体反馈不错，再等等消息"的真相

    评审会后客户说"整体反馈不错，再等等消息"，听起来进展顺利。实际上有人提了担忧但碍于场合没说，需要主动补充材料回应，而不是傻等。

    → 第十章：内部推荐人不是你的盟友，是你的翻译官

  • 给高层汇报的是"决策链已经跑通"

    销售总监准备高层汇报材料时，刻意压缩产品优势篇幅，把更多篇幅放在"技术评估已经通过、安全合规已经确认、实施团队已经就位"——呈现整条决策链已跑通的确定感。

    → 第十一章：向决策链顶端汇报时，你卖的不是方案

2 PART 2 心态层

  • 赢了但赢得侥幸

    团队复盘总结"提前建立了良好的客户关系"为成功原因，实际是合规评审负责人当时正在休产假，代理审批的人相对宽松。这个运气被误记成了方法论。

    → 第一章：复盘不是写你为什么赢了

  • 架构调整后的决策链变化

    客户公司架构调整，采购职能从分散在各业务部门收归集团采购中心。销售没及时意识到变化，继续跟已失去部分权力的业务部门保持密集沟通，直到集团采购中心介入要求重新走比价流程。

    → 第二章：丢单不是因为不够努力，是因为地图没有更新

  • 前辈的长期关系维护习惯

    一位多年大客户销售前辈，不管单子是否签成，都会在项目结束后半年到一年里保持跟关键推荐人低频但持续的联系——可能只是逢年过节问候一句，或者分享一篇相关文章。

    → 第三章：那个帮你说话的人，值得比这一单活得更久的关系

  • 判断失误后的两种反应

    第一种：每次失误都找外部原因，"客户内部太复杂了，谁也没法提前判断"——团队逐渐形成"这个人不愿意正视自己判断问题"的印象。第二种：主动说清楚判断失误的具体环节——团队更信任。

    → 第四章：你把否决人判断错了，团队会怎么看你

  • 擅长处关系 vs 习惯研究权力结构

    非常擅长处关系的销售，业绩并不稳定，因为关系网络覆盖的往往是愿意主动亲近他们的人，而不是真正握着否决权的人。看起来不太会来事的销售，因习惯研究权力结构，业绩反而更稳定。

    → 第五章：这份工作练的是看清权力，不是讨好人
