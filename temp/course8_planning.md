## 模块一：商业化机遇与价值坐标

**为什么现在是最佳时机**

### 学习目标

1. 理解经验萃取从"内部咨询"到"对外变现"的历史性转变
2. 识别AI时代新增的商业变量（AI萃取能力、Agent框架）
3. 建立经验资产商业化的价值坐标图谱

### 核心概念

**知识点 1.1：经验资产化的三次迭代**

```
第一代：访谈 → 文档（写完就沉进知识库）
   ↓
第二代：文档 → 案例库/手册（有人用，但价值随时间衰减）
   ↓
第三代：经验 → 可运行Agent/Skill（可持续运营的商业模式）
```

**知识点 1.2：AI带来的三个新变量**

1. **萃取效率提升**：AI可承担访谈记录整理、初步规则提炼，释放人力到更高价值判断
2. **94.9%知识召回率**：学术研究证明AI Agent可自主开展萃取工作，能在组织复杂性中导航
3. **反直觉发现**：AI从专家实际行为中捕捉的细节，往往和专家嘴上说出来的并不完全一致——AI能发现专家自己都没意识到的行为模式

**知识点 1.3：商业生态的三类玩家**

| 角色 | 定位 | 核心能力 |
|------|------|----------|
| 专家猎头 | 找到谁是真专家 | 识人判断力 |
| 经验陪跑 | 帮不擅长表达的老师傅把经验变成可运行的Agent | 萃取技术 + 转化工程 |
| 推广经纪 | 帮已孵化的经验资产做传播和变现 | 商业运营 + 渠道 |

### 互动形式

**【互动 1-A】价值坐标定位**
> 每人用3分钟完成：对照上面的三次迭代，判断自己的经验萃取能力目前在哪一代？距离第三代还有多远？

**【互动 1-B】商业生态地图**
> 小组讨论：你所在的行业/领域，目前这三类角色各有谁？空白在哪里？

### 学员产出

```
【我的商业化机遇清单】
1. 我目前最接近三类玩家中的哪一类？
2. 我所在的领域，经验资产化的空白点是什么？
3. 如果我要往经验商业化方向发展，第一步该做什么？
```

## 模块二：变现潜力评估四步法

**不是所有经验都值得商业化**

### 学习目标

1. 掌握判断经验资产是否具备对外变现潜力的四步评估法
2. 能够对具体经验资产完成商业化潜力评级
3. 理解"可验收、可复制、可迁移、可回滚"四维评估标准

### 核心概念

**知识点 2.1：变现潜力评估四步法**

```
第一步：真伪判断
  → 这个经验是真正的隐性知识，还是可以轻易公开检索到的显性知识？

第二步：需求验证
  → 市场上是否有人愿意为这个经验付费？付费意愿有多强？

第三步：壁垒评估
  → 这个经验是否容易被复制？你的独特壁垒在哪里？

第四步：交付形态
  → 这个经验能变成什么形态来交付？（课程/咨询/Agent/工具/社群）
```

**知识点 2.2：四维资产质量标准**

| 维度 | 含义 | 评估问题 |
|------|------|----------|
| **可验收** | 成果能被明确评估 | 客户怎么判断这个经验是否有效？ |
| **可复制** | 能被规模化传递给学员 | 不依赖专家本人是否能学会？ |
| **可迁移** | 能跨场景/行业使用 |换一个行业/公司，这个经验还能用吗？ |
| **可回滚** | 出问题能撤回或修正 | 如果判断出错，客户能获得什么保障？ |

**知识点 2.3：潜力评级量表**

```
A级（强烈建议商业化）
  隐性知识 × 高需求 × 高壁垒 × 形态清晰
  → 优先投入资源，尽快产品化

B级（有条件商业化）
  满足3项，但某项明显短板
  → 补足短板后再推进

C级（内部使用为主）
  满足2项及以下
  → 先内部验证，暂不对外

D级（不建议商业化）
  明显可公开获取，或壁垒极低
  → 转向其他更有潜力的萃取方向
```

### 互动形式

**【互动 2-A】四步法实战**
> 用自己萃取过的一个经验资产，完成四步评估，给出评级

**【互动 2-B】案例诊断**
> 给出3个经验资产描述，学员分组判断各属于哪一级别，说明理由

### 学员产出

```
【我的经验资产变现评估报告】
评估对象：
第一步-真伪判断：
第二步-需求验证：
第三步-壁垒评估：
第四步-交付形态：
综合评级：（A/B/C/D）
下一步建议：
```

## 模块三：产品化路径三条路

**从内部沉淀到对外变现的路径设计**

### 学习目标

1. 掌握从内部萃取到对外产品化的三条典型路径
2. 能够根据自身资源禀赋选择最适合的路径
3. 理解不同路径的时间成本、投入资源和收益模型

### 核心概念

**知识点 3.1：三条路径对比**

```
路径一：轻资产路径（课程/工作坊）
  投入：⭐⭐
  时长：3-6个月
  收益：课程学费（一次性）
  核心能力：课程设计 + 交付能力
  适合人群：萃取能力强，营销能力弱

路径二：中资产路径（咨询陪跑）
  投入：⭐⭐⭐⭐
  时长：6-12个月
  收益：项目费 + 持续顾问费
  核心能力：萃取技术 + 客户关系 + 商业运营
  适合人群：有客户资源，想做持续生意

路径三：重资产路径（Agent/Skill产品）
  投入：⭐⭐⭐⭐⭐
  时长：12个月+
  收益：SaaS订阅 / API调用费
  核心能力：萃取技术 + AI工程 + 产品化能力
  适合人群：有技术背景，想做可规模化生意
```

**知识点 3.2：路径选择的四问决策框架**

```
问题一：我现在有什么？（资源盘点）
  萃取能力 / 客户关系 / 技术能力 / 资金储备

问题二：我想做成什么生意？
  一次性收入 / 持续性收入 / 可规模化收入

问题三：我的时间窗口是多久？
  3个月见钱 / 6个月见钱 / 愿意长期投入

问题四：我的核心壁垒是什么？
  课程口碑 / 客户信任 / 技术独特性
```

**知识点 3.3：内部沉淀到对外产品的关键跳跃**

| 内部萃取 | 对外产品 | 关键差异 |
|----------|----------|----------|
| 面向同事 | 面向陌生人 | 需要补足背景信息 |
| 口头交流 | 标准化交付 | 需要流程和验收标准 |
| 免费服务 | 收费产品 | 需要证明价值和差异化 |
| 责任共担 | 独立承担 | 需要建立品牌和信任 |

### 互动形式

**【互动 3-A】路径选择决策**
> 用四问框架，3分钟完成自我诊断，确定最适合的路径

**【互动 3-B）路径升级推演**
> 讨论：走轻资产路径的人，如何逐步向中资产/重资产路径演进？

### 学员产出

```
【我的产品化路径规划】
当前资源盘点：
路径选择（A轻/B中/C重）：
选择理由：
路径起点（第一个可卖的产品形态）：
6个月里程碑：
12个月里程碑：

## 模块四：陪跑经纪人分工模式

**借鉴成熟的商业分工体系**

### 学习目标

1. 理解陪跑经纪人模式的核心逻辑和分工设计
2. 掌握四类关键角色的定位和能力要求
3. 能够根据自身优势找到最适合自己的分工定位

### 核心概念

**知识点 4.1：陪跑经纪人模式的底层逻辑**

> "谁能兼容谁，谁就能领导谁。"

传统模式：一个人完成萃取 + 产品化 + 销售 + 交付
经纪人模式：专业分工，各自做最擅长的事，共享收益

**知识点 4.2：四类角色定位**

```
角色一：专家猎头（Selector）
  职责：找到真专家，评估经验含金量
  核心能力：识人判断力 + 行业洞察
  收益方式：发现费 + 成功佣金
  能力门槛：需要深度行业经验

角色二：萃取工程师（Extractor）
  职责：把专家经验转化为结构化资产
  核心能力：访谈萃取技术 + 结构化能力
  收益方式：项目费
  能力门槛：需要萃取方法论训练

角色三：产品化工程师（Productor）
  职责：把结构化资产转化为可交付产品
  核心能力：课程设计 / Agent开发 / 工具制作
  收益方式：开发费 + 版权费
  能力门槛：需要对应产品技术

角色四：推广经纪（Promotor）
  职责：把产品推向市场，完成商业闭环
  核心能力：获客能力 + 信任建立 + 运营能力
  收益方式：销售佣金
  能力门槛：需要商业网络
```

**知识点 4.3：分工选择的三问**

```
问题一：我的天赋在哪里？（哪个角色最擅长）
问题二：哪个角色在市场上最稀缺？（回报最高）
问题三：我想自己做生意，还是做别人的合伙人？
```

### 互动形式

**【互动 4-A）角色能力自测**
> 对照四类角色，给自己打分（1-5），找到自己的最强角色

**【互动 4-B）分工协作推演**
> 3人小组模拟：分别扮演萃取工程师、产品化工程师、推广经纪，协作完成一个经验资产的商业化

### 学员产出

```
【我的分工定位】
最适合我的角色：
该角色需要的能力：
我的差距：
我的行动计划（补足能力 / 寻找合伙人）：
如果选"自己做生意"：我的第一个MVP是什么？
如果选"合伙人"：我需要找什么样的合伙人？
```

## 模块五：可执行Skill——经验资产的终极形态

**从文档到Agent，从培训到工具**

### 学习目标

1. 理解为什么Skill是经验资产的终极形态
2. 掌握把经验规则封装成可执行Skill的方法
3. 完成自己第一个经验Skill的原型设计

### 核心概念

**知识点 5.1：为什么Skill是终点**

| 形态 | 可验收 | 可复制 | 可迁移 | 可回滚 | 商业价值 |
|------|:------:|:------:|:------:|:------:|:--------:|
| 文档 | ✗ | △ | △ | ✗ | 低 |
| 案例手册 | △ | △ | △ | ✗ | 低 |
| 视频课 | △ | ○ | △ | ✗ | 中 |
| 咨询陪跑 | ○ | ✗ | ✗ | △ | 中 |
| **Skill/Agent** | **○** | **○** | **○** | **○** | **高** |

> Skill = 可直接运行、可测试验收、可复制分发、可版本回滚的组织能力资产

**知识点 5.2：经验Skill的封装逻辑**

```
经验Skill的核心结构：

触发条件（Trigger）
  → 什么情况下调用这个Skill？
  → 例如："当客户提出关于XXX的问题时"

判断规则（Judgment）
  → 面对这个触发条件，应该如何判断？
  → 例如："如果客户处于XXX阶段，则应该XXX"

执行动作（Action）
  → 判断之后，应该给出什么输出？
  → 例如："输出一个包含XXX的分析框架"

验收标准（Validation）
  → 客户怎么判断这个Skill是否有效？
  → 例如："客户用这个框架后，决策速度提升X%"
```

**知识点 5.3：从萃取文档到Skill的转化路径**

```
步骤一：萃取完成
  → 获得结构化访谈记录 + 判断规则清单

步骤二：规则清洗
  → 去掉不可复用的上下文依赖，保留普适性规则

步骤三：触发条件设计
  → 明确这个Skill在什么场景下被调用

步骤四：判断逻辑封装
  → 把"如果...那么..."规则转化为可执行的代码/配置

步骤五：验收标准定义
  → 确定Skill有效性的可量化标准

步骤六：测试与迭代
  → 用真实案例测试，持续优化
```

### 互动形式

**【互动 5-A）Skill结构设计**
> 把自己萃取过的一个经验，尝试用上面的结构设计Skill原型

**【互动 5-B）案例还原：文档 vs Skill**
> 对比：同一份萃取文档 vs 封装后的Skill，运行效果有何不同？

```

核心判断规则（3-5条）：
预期输出：
验收标准：
封装难点：
下一步行动计划：
