# 缺口分析指南

> 如何判断一个分类下"缺什么"——缺口识别的思考框架和方法论

---

## 一、缺口分析的本质

**缺口 = 用户实际需要的场景 - 用户已经想到并创建的场景**

缺口分析不是凭空想象，而是：
1. **先读懂现有内容**：从现有文件名、摘要中推断用户的思路
2. **再对照场景库**：参考行业标准场景库，看缺了哪些
3. **最后主观判断**：结合用户背景，补充可能被忽略的场景

---

## 二、分析三问法

### 第一问：这个分类的核心主题是什么？

```
分析步骤：
1. 看文件夹名称（第一手线索）
2. 读现有文件的内容摘要（印证+补充）
3. 提炼3个以内的主题词

示例：
文件夹名：内容创作
现有文件：爆款标题生成器.md, 金句炼制专家.md
→ 主题词：文案、爆款、传播力
→ 核心主题：帮助用户产出具有传播力的内容
```

### 第二问：该主题下，哪些细分场景尚未覆盖？

```
分析方法：
1. 按用户旅程/工作流展开
2. 按难易程度/复杂度展开
3. 按行业标准场景对照

示例（内容创作）：
用户旅程：选题 → 起草 → 优化 → 发布
缺少的细分：
- 选题阶段：内容矩阵规划师（缺少）
- 起草阶段：长文写作框架（缺少）
- 优化阶段：文案风格转换器（缺少）
- 发布阶段：公众号发布助手（缺少）
```

### 第三问：哪些是用户最可能需要但没想到的？

```
优先级判断：
1. 【高优】该分类的基础/入口场景——用户第一个会想到的
2. 【中优】该分类的高频场景——实际工作中最常用的
3. 【低优】该分类的细分场景——专业用户才需要的

示例（职场）：
- 高优：简历优化专家（入门级，需求广泛）
- 中优：面试模拟教练（求职必备，场景清晰）
- 低优：职场沟通顾问（涉及人际，较为主观）
```

## 三、缺口类型分类

### 类型A：骨架缺失（最严重）

```
特征：该分类最基础、最核心的场景完全不存在
判断标准：该分类的第一个prompt就应该是它
修复策略：优先补全，生成完整高质量版本

示例：
文件夹：创意生成（现有：0个）
→ 骨架缺失：爆款标题生成器（最基础的创意场景）
```

### 类型B：场景覆盖不足（中等）

```
特征：该分类已有部分场景，但核心场景链路不完整
判断标准：按用户旅程检查，每个关键节点至少1个
修复策略：补充关键链路节点

示例：
文件夹：营销（现有：金句炼制专家）
→ 场景覆盖不足：缺少营销策略规划师（营销核心）
→ 场景覆盖不足：缺少用户增长专家（营销目标）
→ 场景覆盖不足：缺少活动策划生成器（营销落地）
```

### 类型C：深度不够（较轻微）

```
特征：该分类核心场景已有，但细分维度不足
判断标准：同类场景重复，不同维度场景缺失
修复策略：补充其他维度的场景

示例：
文件夹：创意生成（现有：金句炼制专家、爆款标题生成器）
→ 维度不足：已有"文字创意"，缺少"视觉创意"（分维度）
→ 补充：UI组件设计器（视觉创意维度）
```

## 四、场景推荐策略

### 空文件夹策略（现有=0）

```
策略：建立骨架，而非填满
原则：5个场景覆盖分类最核心的5个维度

选择逻辑：
1. 第1个：最基础的入口场景（降低门槛）
2. 第2个：最常用的核心场景（最高频）
3. 第3个：次常用但重要的场景
4. 第4个：专业用户场景
5. 第5个：差异化/亮点场景

示例（心理成长）：
1. 职业规划顾问（入口，降低门槛）
2. 目标分解教练（高频，实际刚需）
3. 习惯养成设计器（常用，生活应用）
4. 自我认知探索器（深度，成长核心）
5. 情绪调节顾问（差异化，心理特色）
```

### 稀疏文件夹策略（现有1-3个）

```
策略：查漏补缺，而非重复
原则：3个场景，重点补充关键链路

选择逻辑：
1. 分析现有场景处于用户旅程的哪个节点
2. 补充上游和下游的场景
3. 避免与现有场景类型重复

示例（内容创作，现有：金句炼制专家）：
- 现有：金句炼制（优化阶段）
- 缺口：选题阶段 → 内容矩阵规划师
- 缺口：起草阶段 → 长文写作框架
- 缺口：发布阶段 → 公众号发布助手
```

### 中等文件夹策略（现有4-8个）

```
策略：精细化补充
原则：2个场景，精准匹配

选择逻辑：
1. 识别现有场景未覆盖的细分维度
2. 找用户实际需要但未想到的边缘场景
3. 避免与现有场景同质化
```

### 成熟文件夹策略（现有>8个）

```
策略：主动告知，尊重已有
原则：不强制补全，如有建议需有理有据

策略：
1. 告知用户"该分类已较为完善"
2. 如有补充建议，说明具体理由
3. 询问用户是否需要补充
```

## 五、智能匹配设计模式

### 模式匹配三原则

```
1. 场景目标决定模式
   → 目的是"自动化执行" → 技术工具型
   → 目的是"扮演某人" → 角色扮演型
   → 目的是"引导思考" → 启发引导型

2. 输出形态影响模式
   → 输出是"可执行代码/工具" → 技术工具型
   → 输出是"对话内容" → 角色扮演型
   → 输出是"方案/策略" → 分类型框架型

3. 用户交互方式影响模式
   → 用户说"帮我做" → 技术工具型
   → 用户说"像谁一样" → 角色扮演型
   → 用户说"引导我思考" → 启发引导型
```

### 典型场景→模式映射

```
金句炼制专家 → 创意生成型
代码审查专家 → 角色扮演型
简历优化专家 → 内容转换型
AI职业规划导师 → 启发引导型
多角色协作系统 → 多角色协作型
品牌slogan生成器 → 创意生成型
产品经理数字分身 → 人格复刻型
互动内容转化师 → 双重输出型
内容分类处理专家 → 分类型框架型
技能生成专家 → 元Skill生成型
```

## 六、质量保证

### 缺口识别的常见错误

```
❌ 错误1：把同质场景当成新场景
   → 案例：金句炼制专家 + 爆款文案专家 → 其实是同一个
   → 修正：检查场景核心目标是否相同

❌ 错误2：脱离用户实际需求
   → 案例：心理文件夹补充"量子波动速读"（用户不需要）
   → 修正：缺口必须有实际使用场景

❌ 错误3：数量优先而非质量
   → 案例：为了凑数补充10个，实际有效只有2个
   → 修正：宁可少而精，不要多而滥

❌ 错误4：忽视现有内容
   → 案例：没读现有文件就推荐，重复率极高
   → 修正：必须先扫描再分析
```

### 缺口识别的自检清单

```
□ 我是否完整读取了该文件夹下的所有现有文件？
□ 我是否正确理解了用户的实际使用场景？
□ 我推荐的场景与现有场景是否同质？
□ 我推荐的场景是否有实际使用价值？
□ 我推荐的场景数量是否符合成熟度策略？
□ 我是否为每个推荐匹配了正确的设计模式？
□ 我是否规划了合理的序号（接续现有）？
□ 我的推荐理由是否具体而非泛泛而谈？
```

---

*缺口分析不是一次性的判断，而是一个需要结合"现有内容理解 + 行业知识 + 用户背景"综合决策的过程。*
