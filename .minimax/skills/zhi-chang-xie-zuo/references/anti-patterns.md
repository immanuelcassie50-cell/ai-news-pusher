# 职场写作反模式

## 核心理念：识别陷阱，在约束层不突破

反模式的作用是帮助AI识别什么时候违反了约束层要求。
每一条"错误示例"都是突破了某个约束，每一条"正确示例"都是满足了某个约束。

---

## 易混淆场景

### 职场写作 vs 文学创作

| 维度 | 文学创作 | 职场写作 |
|------|----------|----------|
| 核心 | 表达自我 | 促成结果 |
| 目标 | 启发思考 | 明确行动 |
| 表达 | 可以感性 | 必须克制 |
| 受众 | 主观解读 | 客观理解 |

**陷阱表现：** 写得像散文、像日记、像个人感想

### 职场写作 vs 个人日记

| 维度 | 个人日记 | 职场写作 |
|------|----------|----------|
| 情绪 | 可以情绪化 | 必须克制 |
| 精确度 | 可以模糊 | 必须精确 |
| 受众 | 只有自己 | 任何人 |

**陷阱表现：** "我觉得""我认为"出现在正式文档中

## 周报陷阱

### 陷阱1：只写"做了什么"，不写"达成了什么"

```
❌ 错误示例：
- 完成了需求文档
- 参加了评审会
- 对接了开发团队

✅ 正确示例：
- 完成20页需求文档，已归档至Notion
- 推动3个需求通过评审，高优先级需求已锁定开发资源
- 对接开发团队，确认Q2技术方案可行
```

**约束层要求：** 每项都要写产出物和结果

---

### 陷阱2：写成流水账，没有结构

```
❌ 错误示例：
- 周一：写文档
- 周二：开会
- 周三：改文档
- 周四：开会
- 周五：写周报

✅ 正确示例：
✅ 已完成
  | 事项 | 成果 | 状态 |
  | 需求文档 | 20页，已归档 | 完成 |
  | 需求评审 | 3个需求通过 | 完成 |

🔄 进行中
  | 事项 | 进度 | 阻塞 |
  | 新功能开发 | 方案设计完成 | 开发资源紧张 |
```

**约束层要求：** 必须有已完成/进行中/计划的结构

---

### 陷阱3：没有时间节点，没有交付物

```
❌ 错误示例：
- 继续跟进项目
- 持续优化产品

✅ 正确示例：
- 3月22日前输出详细需求文档
- 3月底前完成A/B测试，输出测试报告
```

**约束层要求：** 所有计划都要有截止时间

## 会议纪要陷阱

### 陷阱1：写成"会议记录"，而不是"行动清单"

```
❌ 错误示例：
- 张三说了要优化流程
- 李四觉得可以试试新方案
- 王五认为需要更多资源

✅ 正确示例：
📋 决策记录
  | 议题 | 结论 | 备注 |
  | 流程优化 | 确定Q2启动 | 责任人：张三 |

📌 待办事项
  | 待办 | 负责人 | 截止时间 | 交付物 |
  | 输出流程优化方案 | 张三 | 2024-03-22 | 方案文档 |
```

**约束层要求：** 决策和待办必须分开

---

### 陷阱2：缺少责任人或时间节点

```
❌ 错误示例：
- 继续跟进
- 待办事项：优化流程

✅ 正确示例：
- 张三：3月22日前输出流程优化方案，交付物为文档
```

**约束层要求：** 每条待办必须有责任人 + 截止时间 + 交付物

---

### 陷阱3：讨论过程代替决策结果

```
❌ 错误示例：
- 讨论了产品路线图，有人说做A好有人说做B好，后来决定先做调研

✅ 正确示例：
📋 决策记录
  - Q2产品路线图：3个功能（功能A、功能B、功能C）
```

**约束层要求：** 记录结论，不记录讨论过程

## 申请报告陷阱

### 陷阱1：只说"需要什么"，不说"为什么需要"

```
❌ 错误示例：
- 需要追加30万预算
- 请批准

✅ 正确示例：
申请背景
  1. 当前预算完成率预计仅达65%，存在显著缺口
  2. 竞品Q1投入增长40%，市场份额开始被侵蚀
  3. 行业旺季即将到来，错失窗口影响全年目标

申请内容
  追加预算30万元
```

**约束层要求：** 必须先说理由，再说请求

---

### 陷阱2：数字模糊，无法评估

```
❌ 错误示例：
- 预期效果很好
- 预计能大幅提升

✅ 正确示例：
  | 指标 | 当前 | 引入后 | 提升 |
  | 响应时长 | 8分钟 | 2分钟 | 75% |
  | 重复咨询率 | 35% | 12% | 66% |
```

**约束层要求：** 预期回报必须量化

---

### 陷阱3：没有承诺，没有担当

```
❌ 错误示例：
- 希望领导批准
- 希望能得到支持

✅ 正确示例：
- 若Q2目标未达成，将按比例扣减下半年预算额度
```

**约束层要求：** 申请要有承诺，让决策者知道风险可控

---

## 复盘报告陷阱

### 陷阱1：写成"功劳簿"，只讲做得好的

```
❌ 错误示例：
- 今年完成了所有目标
- 团队表现优秀
- 得到了领导认可

✅ 正确示例：
✅ 做对了的事
  1. 分批迁移策略：采用先试点后扩展，降低数据风险

❌ 踩过的坑
  1. 技术评估不足：低估了数据清洗复杂度，导致2周延期
     - 避坑建议：涉及旧系统迁移的项目，技术评审必须加入数据团队
```

**约束层要求：** 必须有"做对了"和"踩过了"两部分

---

### 陷阱2：踩坑只写"问题"，不写"影响"和"建议"

```
❌ 错误示例：
- 技术评估不足
- 中途遇到问题

✅ 正确示例：
❌ 技术评估不足
  - 问题：低估了历史数据清洗的复杂度
  - 影响：导致2周延期，影响Q2目标达成
  - 避坑建议：涉及旧系统迁移的项目，技术方案评审必须加入数据团队
```

**约束层要求：** 每个坑都要有"问题→影响→建议"的结构

---

### 陷阱3：没有交接清单，没有注意事项

```
❌ 错误示例：
- 项目已完成，所有文档都在共享盘

✅ 正确示例：
📋 交接清单
  | 内容 | 位置 | 备注 |
  | 产品需求文档 | /docs/requirements.md | 最新版本 |

⚠️ 接手后注意事项
  - 数据迁移未完全，约5000条历史数据待清洗
```

**约束层要求：** 必须有实用信息帮助接手人快速上手

---

## 方案建议陷阱

### 陷阱1：只有方案，没有问题

```
❌ 错误示例：
- 建议引入智能客服系统
- 系统功能：智能接待、FAQ知识库、智能推荐

✅ 正确示例：
背景：客服团队面临的挑战
  | 指标 | 当前 | 目标 | 差距 |
  | 平均响应时长 | 8分钟 | <3分钟 | -62% |
```

**约束层要求：** 必须先量化问题，再说方案

---

### 陷阱2：只有功能，没有实施路径

```
❌ 错误示例：
- 系统功能完善
- 能解决当前问题

✅ 正确示例：
实施路径
  | 阶段 | 时间 | 内容 |
  | 试点 | 第1-2月 | 选择1条业务线试点 |
  | 扩展 | 第3-4月 | 全量接入 |
  | 迭代 | 第5-6月 | 持续优化 |
```

**约束层要求：** 必须有实施路径，让决策者看到怎么落地

---

### 陷阱3：没有风险预案

```
❌ 错误示例：
- 建议引入智能客服系统，预计效果很好

✅ 正确示例：
风险与应对
  | 风险 | 应对 |
  | 客服人员抵触 | 已设计"人机协作"模式，客服角色转为"复杂问题专家" |
```

**约束层要求：** 必须有风险识别和应对方案

## 竞聘报告陷阱

### 陷阱1：只有"今年做了什么"，没有"我能做什么"

```
❌ 错误示例：
- 完成了品牌曝光提升80%
- 获得了2个行业奖项
- 搭建了内容中台

✅ 正确示例：
我的核心优势
  1. 业务能力：从一线执行到全面负责
  2. 团队管理：带领8人团队，年人均产值提升50%
  3. 资源整合：50+媒体资源积累

明年规划
  目标：市场ROI提升至1:5
```

**约束层要求：** 必须有"我能做什么"的能力定位部分

---

### 陷阱2：写成"功劳簿"，没有"价值定位"

```
❌ 错误示例：
- 今年完成了X
- 获得了Y奖项
- 希望能够晋升

✅ 正确示例：
核心定位
  从"执行优秀"到"战略胜任"——我完成了从业务执行者到团队管理者的转型
```

**约束层要求：** 必须有一句话概括你的核心价值

---

### 陷阱3：结尾写成"请求"而非"说服"

```
❌ 错误示例：
- 希望领导能够批准我的竞聘申请
- 请领导考虑我的晋升

✅ 正确示例：
如果给我一个更大的舞台，我能把同样的能力复制到更大的战场。
```

**约束层要求：** 结尾要有说服力，不是请求批准

## 质量红线检测清单

### 原则一：导向行动

- [ ] 文档有一个明确的"下一步"吗？
- [ ] 读者知道他们需要做什么吗？
- [ ] 有时间节点吗？

### 原则二：用户意识

- [ ] 我知道这份文档给谁看吗？
- [ ] 我知道他们的关注点是什么吗？
- [ ] 信息排列是按读者逻辑，不是按我的逻辑？

### 原则三：默认公开

- [ ] 每一个数据都有来源吗？
- [ ] 表达克制，没有情绪化词汇吗？
- [ ] 前后文逻辑自洽吗？

## AI自主空间：识别什么时候可以用空间层

**以下情况，可以使用空间层灵活处理：**

1. **受众是高层决策者** → 可以简化结构，结论靠前
2. **内容非常简单** → 可以跳过某些模块，直接说结论
3. **时间非常紧张** → 可以用清单代替段落
4. **内容非常复杂** → 可以加模块便于选择性阅读

**以下情况，必须严格遵守约束层：**

1. **涉及资源申请** → 理由必须充分，数据必须准确
2. **涉及人员变动** → 事实必须可核实，表达必须克制
3. **涉及正式存档** → 逻辑必须自洽，格式必须规范
4. **涉及跨部门协作** → 责任必须明确，时间必须清晰
