# Team 模式规范

> Team 模式下自动生效。详细规范见本文件。

## 核心原则

Team 模式下，**每个 subagent 必须遵守以下规则**，防止空转卡死：

### 1. 必须主动报告进度

Subagent 每次完成一个阶段任务后，**必须向主控发送进度消息**：

```
格式: SendMessage(to: "team-lead", message: "✅ [任务名] 阶段完成: [具体内容] | 剩余: [待办]")
示例: SendMessage(to: "team-lead", message: "✅ research 完成: 已收集 10 条竞品信息 | 剩余: 整理分析报告")
```

**禁止行为**: 埋头干活不汇报，让主控不知道进度。

### 2. 超时强制终止

如果 subagent 运行超过 **5 分钟** 无输出，视为卡死：

- 主控直接使用 `TaskStop` 终止
- Subagent 必须设置合理的阶段性检查点
- 每个检查点最多 2 分钟

### 3. 死循环检测

如果 subagent 出现以下迹象，**立即向主控报告并请求确认**：

- 同一文件反复 Edit（超过 3 次同一位置）
- 连续 3 次 SendMessage 内容相似
- 工具调用输出"already exists" / "nothing to do" 超过 2 次

### 4. 异常上报

遇到以下情况，**立即停止并上报主控**，不要自己猜测处理：

- API 错误/网络错误
- 权限不足
- 文件找不到
- 任务超出初始范围

### 5. 主动请求确认

模糊情况不要猜，发送消息给主控：

```
SendMessage(to: "team-lead", message: "⚠️ [问题描述] | 我的判断: [A/B] | 请确认方向")
```

### 6. 接受主控接管

- 主控随时可以接管任何任务
- 收到接管通知后，立即停止并交接上下文
- 不要争辩，不要继续原任务

---

## 主控职责

- 监控 subagent 进度，**超过 3 分钟无消息则主动询问**
- 收到异常报告立即干预
- 不要让 subagent 独自处理未知的复杂情况

## 主控自主决策权

**主控可以自主判断并立即接手的情况：**

1. **subagent 超过 5 分钟无实质性进展** → 直接 TaskStop，接手任务
2. **subagent 报告错误或异常** → 接手处理
3. **任务范围变更超出初始分配** → 接手并重新分配
4. **发现 subagent 方向错误** → 立即纠正或接手
5. **用户语气不耐烦** → 主动汇报进度，询问是否接手

**接管流程：**
```
1. TaskStop {subagent-id}
2. SendMessage(to: "all", message: "⚠️ 主控接管 [任务名]，原因: [简短说明]")
3. 直接处理原任务
4. 如需重新分配，创建新 subagent
```

**用户干预方式（可选）：**
- 直接说"接手"或"主控来"→ 主控立即接管
- 说"继续等"→ 主控继续监控
- 说"停掉重来"→ 终止 + 重新规划
